# Передача проекта: синхронизация остатков с маркетплейсами

Документ для программиста, который **развернёт приложение на сервере** и
**добавит обработку в 1С**. Это единая точка входа — отсюда ссылки на детали.

---

## 1. Что это и из чего состоит

Система синхронизирует остатки товара между базой **1С «Магазин одежды и обуви»**
и маркетплейсами (**WB, Ozon, Kit/Яндекс**), принимает заказы и делает под них
перемещения товара в 1С.

Два компонента, оба на **одном сервере** (Windows Server `136.243.92.95`,
WIN-Q0QVP2SM59L):

| Компонент | Что | Где |
|---|---|---|
| **Приложение sync_admin** | FastAPI-веб (админка) + фоновый планировщик (опрос заказов, рассылка остатков, сверка) | Python, этот репозиторий |
| **Обработка `ОбменССайтом.epf`** | 1С-сторона: остатки ЦС ⇄ перемещения под заказы | 1С, папка `1c/` |

Обмен между ними — через **локальную папку** `C:\sync\{tasks,results,archive}`
(без FTP; всё на одной машине).

```
Маркетплейсы  ──API──►  Приложение  ──файлы C:\sync──►  1С (.epf)  ──►  документы/остатки
     ▲                      │                              │
     └──────остатки─────────┘◄─────остатки/результаты──────┘
```

## 2. Часть A — развернуть приложение (Windows)

Подробности и управление службами — в **`deploy/README_WINDOWS.md`**.

### Предпосылки (поставить заранее)
- **Python 3.11–3.14** (при установке — «Add to PATH»).
- **PostgreSQL для Windows** (рекомендуется; иначе скрипт возьмёт SQLite).
- **NSSM** (`nssm.exe` в PATH) — для служб автозапуска.

### Установка одной командой
PowerShell **от администратора**, из корня проекта:
```powershell
powershell -ExecutionPolicy Bypass -File deploy\install_windows.ps1
```
Скрипт: создаёт venv и ставит зависимости; создаёт `C:\sync\...`; генерирует `.env`
с секретами; настраивает БД; прогоняет миграции (`alembic upgrade head`); создаёт
пользователя `admin` (пароль показывается **один раз**); регистрирует и запускает
службы `sync_admin_web` (порт 8000) и `sync_admin_worker`.

### После установки — в админке
1. Открыть `http://127.0.0.1:8000/login`, войти под выданным admin.
2. Страница **«API-ключи»** — по каждому кабинету WB/Ozon/Kit ввести токены и
   `ID склада на площадке` (кнопка «Проверка подключения» сразу скажет, валиден ли ключ).
3. В `.env` заполнить `WAREHOUSE_ID_WB/OZON/KIT` (ID склада продавца на площадке) —
   и `nssm restart sync_admin_worker`.
4. Убедиться, что папка `C:\sync` та же, что в 1С (`ПараметрыОбмена()` в обработке).

### ⚠️ Важные ДЕФОЛТЫ (безопасные — ничего не уезжает само)
- **Трансляция остатков SKU по умолчанию ВЫКЛючена.** Новый товар не льёт остаток
  на площадки, пока его явно не включат на странице **«Управление остатками»**.
- **Синхронизация товара по кабинету** (страница «Синхронизируемые товары») тоже по
  умолчанию выключена.
Оператор включает нужные SKU/кабинеты вручную (в т.ч. массово).

## 3. Часть B — добавить обработку в 1С

Полное ТЗ для 1С-стороны — **`1c/ТЗ_ОбменССайтом.md`** (протокол файлов, метаданные,
логика, приёмочный тест). Готовый код модуля — **`1c/ОбменССайтом_МодульОбъекта.txt`**.

Коротко:
1. Конфигуратор → Файл → Новый → **Внешняя обработка**, имя `ОбменССайтом`.
2. **Модуль объекта** → вставить `1c/ОбменССайтом_МодульОбъекта.txt`.
3. Добавить форму с кнопкой, вызывающей `ВыполнитьОбмен()` (или регламент).
4. **Ctrl+F7** (синтаксический контроль) → должно быть чисто.
5. Файл → Сохранить как → `ОбменССайтом.epf`.
6. **Проверить проведение** документа `ПеремещениеТоваров` на тестовом задании
   (обязательные реквизиты / дата запрета / контроль остатков — см. ТЗ, п. 12).
7. Настроить **автозапуск** (регламент / «Дополнительные обработки»).

### Склады в 1С (создать/назвать точно так)
Обработка ищет склады по наименованию. Имена уже прописаны в коде:

| Роль | WB | Ozon | Kit (магазин «Сайт AWER») |
|---|---|---|---|
| Источник (остаток) | `ЦС Склад` | `ЦС Склад` | `ЦС Склад` |
| «В пути» (резерв) | `Wildberries_Впути` | `OZON_Впути` | `AWER в пути` |
| Склад площадки | `Wildberries_Склад_FBO` | `OZON_Склад` | `Сайт AWER` |

Жизненный цикл заказа: `ЦС Склад` → `…_Впути` (заказ) → `…_Склад` (подтверждён)
или → `ЦС Склад` (не подтверждён). Подтверждённый заказ терминален.

### Приёмочный тест канала
Положить в `C:\sync\tasks` файл `task_test.txt` (UTF-8):
```
CREATE_MOVEMENT|<баркод с остатком на ЦС Склад>|ЦС Склад|Wildberries_Впути|1|TEST-1|wb
```
Запустить обработку → в `C:\sync\results` появится `result_*.txt` с `TEST-1|OK|<номер>`,
файл уедет в `archive`, в 1С — проведённый документ перемещения.

## 4. Переменные окружения (`.env`)

Генерируются скриптом; ключевые:
```
DATABASE_URL=postgresql://sync_user:...@localhost:5432/sync_admin   # или sqlite:///...
SESSION_SECRET=...            # сгенерирован
SECRETS_ENCRYPTION_KEY=...    # Fernet, шифрует API-ключи в БД
SESSION_COOKIE_SECURE=0       # локальный HTTP; за HTTPS-прокси → 1
WAREHOUSE_ID_WB=...  WAREHOUSE_ID_OZON=...  WAREHOUSE_ID_KIT=...      # ID склада на площадке
SYNC_DIR_TASKS=C:\sync\tasks  SYNC_DIR_RESULTS=C:\sync\results  SYNC_DIR_ARCHIVE=C:\sync\archive
```
Приложение подхватывает `.env` само (`app/__init__.py`, `load_dotenv`).
Секреты в БД — зашифрованы (Fernet); `.env`, `*.db` — не коммитить.

## 6. Что НЕ доделано (честно)

1. **HTTP-клиенты площадок не проверены на реальных ключах** — их пока нет в
   системе. Код написан по документации; «Проверка подключения» на странице
   API-ключей — первый шаг валидации.
2. **Детект статуса «заказ подтверждён»** по каждому живому API (WB `supplierStatus`,
   Ozon posting status, Kit статус) — не заполнен. Пока не заполнен, движение
   `…_Впути → …_Склад` в проде не создаётся (см. `get_confirmed_orders` в
   `app/workers/platform_clients/base.py`).
3. **Backfill «старт задним числом»** (Фаза 2): поле `broadcast_active_since` есть,
   но подтягивание отгрузок маркетплейсов с даты — НЕ реализовано.
4. **Автозапуск обработки 1С по расписанию** — согласовать способ (регламент /
   «Дополнительные обработки»), см. ТЗ п. 10.
