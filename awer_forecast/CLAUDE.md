# AWER Forecast — инструкции для Claude Code

Прогноз спроса, пополнение FBO Lamoda и закупка у поставщика для бренда AWER (мужская одежда).
Каналы: Lamoda (FBO, склад площадки), WB и Ozon (FBS), сайт awer-russia.ru (Яндекс KIT, `own_site`).
Единый источник закупки — центральный склад (ЦС) в 1С. Состояние и запуск — `README.md`.

## Перед любой правкой
1. Тесты: `cd awer_forecast && .venv/bin/python -m pytest -q` — все зелёные. С PostgreSQL:
   `FORECAST_TEST_PG_URL=postgresql+psycopg://…/postgres` (проверяет, что миграции = schema.sql).
2. Изменил `forecast/db/schema.py` → новая миграция:
   `FORECAST_DATABASE_URL=postgresql+psycopg://…/пустая_база_на_head .venv/bin/alembic revision --autogenerate -m "…"`.
   Генерировать против PostgreSQL, затем заменить `sa.text('now()')` → `sa.func.now()`, `sa.text('false')` →
   `sa.false()` (иначе миграция не пойдёт на SQLite), проверить глазами, прогнать вверх/вниз на обеих СУБД.
   Новое отличие от schema.sql — объявить в `tests/test_schema.py` (PHASE1_NEW_*), иначе тест упадёт.
3. Не ломать демо: `python -m forecast demo` должен проходить весь цикл без ошибок.

## Критичные правила реализации (из передачи)
1. **Lamoda API только v2** (`https://public-api-seller.lamoda.ru/api`). v1 отключается 01.01.2027.
2. Суммы Lamoda — целые в минорных единицах, в v2 объекты `{amount, currency}`; ÷100 только на границе
   приёма (`integrations/lamoda/money.py`).
3. Токен: время жизни из `expires_in`, обновление заранее (за 30–60 с) и по 401 (один повтор).
4. Пагинация: 25 на странице у nomenclatures/minimal-prices/sell-values, до 1000 у остальных. Незнакомые
   query-параметры API молча игнорирует — проверять ответ (см. `LamodaFilterIgnored`).
5. Ошибки `{"error":{code,message,details}}`; `403` чаще всего = неверный `sellerId`. Незнакомые поля и
   enum-значения ответа игнорировать/логировать, не падать.
6. **HTTP 200 ≠ успех** при записи цен: парсить `errors[]`, `priceStatuses`, `fraudValidationResult`
   (Фаза 2). FBS и FBO — разные методы.
7. **Вебхуки — только ускоритель.** Источник истины — опрос `GET /v2/orders` по `updatedAtFrom`.
   Идемпотентность по «id заказа + позиция + статус»; путь `/v2/orders/{id}` — внутренний `id`, не `orderId`.
8. **Сопоставление SKU — по пулу баркодов**: совпадение любого одного баркода из `barcode_pool` достаточно
   (`catalog/resolver.py`). Баркод другого размера не перепривязывать молча.
9. Спрос цензурировать до обучения; закупка — по суммарному спросу всех каналов
   (`central_stock_aggregate_demand`).
10. Пороги и ставки — настраиваемые (`.env` / `margin_settings`), не константы в коде.
11. Секреты — только в `.env`, не в репозитории и не в логах.

## Решения владельца (21.10.2026, подробнее — README)
- Спрос магазинов, WB, Ozon и сайта — **из 1С** (выгрузка обработки «бота план продавцов» + при
  необходимости перемещения Sync Admin). Не добавлять потоки WB/Ozon/KIT из API площадок поверх
  1С-каналов: спрос задвоится. Lamoda — только из API, в 1С-данных канал `lamoda` не принимается.
- Отгрузка на FBO списывается с ЦС в 1С после создания поставки в Lamoda: товар незавершённой поставки
  в статусах «до прибытия» (`SHIPMENT_ON_CS_STATUSES`, `PLAN_FBO_STATUSES_ON_CS`) ещё в остатке ЦС —
  не отгружать его повторно и не считать дважды в закупке.

## Соседи по репозиторию
- **Sync Admin** (корень репозитория) владеет FTP-мостом 1С (`C:\sync`). Эта система файлы обмена
  только ЧИТАЕТ и никогда не переносит/не удаляет: `stock_*.txt` забирает Sync Admin, и остаток на
  площадки уходит оттуда. Новые команды для 1С — только вместе с правкой `1c/` и `1c/README.md`.
- Клиент Яндекс KIT для сайта (Фаза 3) — переиспользовать `app/workers/platform_clients/kit.py`, не писать заново.
- Новая база на сервере → строка в корневом `BACKUPS.md` и копия на вторую площадку.

## Границы автономности
Сам: код, тесты, миграции, демо. Спрашивать перед: правкой `.env` на сервере, запуском против живых
ключей Lamoda (сначала по одному шагу, смотреть сводки), любыми изменениями обработки 1С, записью цен
в Lamoda (Фаза 2 — только по явному подтверждению менеджера, как в разделе 6 ТЗ).
