## 12. Порядок реализации (для перехода в Claude Code)

Документ большой (полный контекст проекта, не пошаговый план) — чтобы не пытаться поднять всё разом, реализация двигается фазами. Каждая фаза даёт рабочий результат сама по себе, не ждёт следующую:

**Фаза 1 — MVP без ML.** Схема БД целиком (можно развернуть сразу — таблицы не создают циклических зависимостей по фазам). 1С (остатки ЦС) + Lamoda API v2 (остатки FBO, продажи) — ежедневный опрос, без вебхуков пока. Простая точка заказа (раздел 5.5, без SBC/бэктеста — плоское сглаживание как первый прогноз). Страницы 1 и 2 раздела 6 (поставка на FBO / закупка у поставщика) с Excel-выгрузкой — это то, что реально нужно в работе с первого дня.

**Фаза 2 — Прогноз становится умнее, только Lamoda.** SBC-классификация + бэктест-турнир (раздел 5.2, без DeepAR — TSB/CrostonSBA/сглаживание/бустинг достаточно на старте). Цензурирование по stockout (раздел 5.1). Вебхуки вместо чистого опроса (раздел 4/7) — ускоряют реакцию. Маржинальность Lamoda (раздел 5.7) со всеми тремя проверками цены (карантин/медиана/фрод, раздел 6).

**Фаза 3 — Многоканальность.** WB/Ozon постоянные потоки (раздел 4) + `channel` на `demand_forecast`/`margin_calc` + `central_stock_aggregate_demand` (раздел 5) — страница 2 раздела 6 начинает учитывать агрегированный спрос, не только Lamoda. Историческая выгрузка WB/Ozon/розница (раздел 4) — сезонный индекс + метод для новинок с историей на другом канале (раздел 5.6). Собственный сайт — заказы через Яндекс KIT API (`api.kit.yandex.net`), переиспользуя клиент из AWER CRM / Sync Admin.

**Фаза 4 — Продвинутое.** DeepAR/GluonTS как шестой кандидат бэктеста (раздел 5.2) — тяжелее в реализации и по ресурсам (раздел 7.1), ценно, но не блокирует остальное. Ценовая эластичность/сценарии/A-B-тест (раздел 5.10) и оптимизация по линейке (раздел 5.11). AI-агенты (раздел 8) — vision-теги и триаж аномалий. Детектор недооценённого потенциала (раздел 5.6) и степень достоверности (раздел 5.8/6) — оба зависят от накопленной истории по нескольким фазам сразу, раньше смысла не имеют.

Открытые вопросы (раздел 9) не блокируют фазу целиком — большинство имеют заложенный fallback (параметр по умолчанию, ручная сверка) и решаются по ходу, не до старта разработки.
