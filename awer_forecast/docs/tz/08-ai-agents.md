## 8. AI-агенты

Агенты используются только там, где нужна интерпретация неструктурированных данных или суждение в пограничных случаях. Основной расчётный контур (прогноз спроса, точка заказа, маржа, ABC-классификация) остаётся чистой арифметикой — без LLM, ради воспроизводимости и объяснимости.

### 8.1 Vision-агент: подбор тегов фасона

**Назначение:** повышает точность подбора аналогов для новинок (раздел 5.6) — вместо сходства только по категории/цене/сезону добавляет сходство по силуэту/фасону.

**Перед запуском — проверка `v1.attributes.sku.list`.** У категории может уже быть нужный атрибут (фасон/посадка/силуэт), заполненный вами при создании карточки — тогда он надёжнее и дешевле, чем вывод по фото. Vision-агент запускается только если у категории нет подходящего структурированного атрибута.

```
Вход:  фото карточки SKU (URL из карточки Lamoda / собственного каталога)
Модель: Claude vision
Выход: sku_id, теги_фасона[] (из фиксированной таксономии — оверсайз, приталенный,
       принт, длина, посадка и т.п.), confidence
```

**Триггер:** при заведении новой карточки/новинки — разово, не периодическая задача.

**Human-in-the-loop:** если `confidence` низкий, или агент предлагает тег вне существующей таксономии — карточка помечается на ручную проверку, а не пишется в справочник автоматически.

**Куда пишет:** поле `теги_фасона` в справочнике товара (раздел 3) → используется в расчёте `вес_сходства` в справочнике аналогов.

### 8.2 Агент триажа аномалий воронки

**Назначение:** когда по SKU одновременно срабатывает несколько сигналов (падение конверсии в корзину + рост возврата + скачок курса и т.п.) — вместо того, чтобы менеджер вручную реконструировал причину по таблицам, агент формулирует вероятный диагноз.

```
Вход:  набор сработавших сигналов по SKU за период
       (доля отменённых/недоставленных заказов, возвратность, курс USD, флаг неликвида, изменение маржи)
Модель: LLM (reasoning), структурированный вывод
Выход: sku_id, вероятная_причина, рекомендуемое_действие, уверенность
```

**Триггер:** батч-джоб (ежедневно/еженедельно), запускается только для SKU, где сработало ≥ 2 сигнала одновременно — единичные сигналы и так покрыты детерминированными правилами из раздела 5.3, агент не дублирует их.

**Human-in-the-loop:** менеджер подтверждает или отклоняет рекомендацию агента. Решения (подтверждено/отклонено) логируются — это будущая обучающая выборка для калибровки правил, а не для дообучения модели.

**Связь с ценовыми рекомендациями (решено):** если менеджер подтверждает диагноз, объясняющий отклонение маржи неактуальной причиной (например, «маржа упала из-за курса, это нормально») — связанная автоматическая рекомендация по цене (раздел 5.7) для этого SKU и периода подавляется, а не выполняется автоматически. Статус рекомендации меняется на "suppressed" со ссылкой на запись триажа, которая это вызвала.
