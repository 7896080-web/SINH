# ТЗ: внешняя обработка «ОбменССайтом»

Обмен остатками и заказами между базой 1С и сервисом синхронизации маркетплейсов
(WB / Ozon / Kit) через локальную папку.

---

## 1. Назначение

Внешняя обработка `ОбменССайтом.epf` — это 1С-сторона канала обмена с приложением
синхронизации остатков. Приложение управляет остатками товара на маркетплейсах и
принимает заказы; 1С — источник физического остатка и исполнитель перемещений
товара под заказы. Обмен идёт через файлы в общей локальной папке.

Обработка должна:

1. **Отдавать остатки** центрального склада (ЦС) по запросу приложения.
2. **Создавать и проводить перемещения** товара под заказы маркетплейсов:
   - при заказе: `ЦС → склад «в пути» площадки` (резерв);
   - при подтверждении заказа: `склад «в пути» → склад площадки` (продано/отгружено);
   - при отмене неподтверждённого заказа: реверс обратно на ЦС.
3. **Возвращать результат** по каждому заданию (номер документа или текст ошибки).

Продажу и возврат ПОСЛЕ подтверждения приложение не присылает — подтверждённый
заказ терминален.

## 2. Контекст и платформа

- **Платформа:** 1С:Предприятие **8.3.9.2233** (клиент-серверная, сервер localhost,
  база `modus_new`).
- **Конфигурация:** «Магазин одежды и обуви», ред. 1.0.16.x.
- Обмен — через **локальную папку** (1С, приложение и папки — на одном сервере
  `136.243.92.95` / WIN-Q0QVP2SM59L). FTP **не используется**.
- Учёт размер-цвета ведётся **характеристиками номенклатуры**
  (`Справочник.ХарактеристикиНоменклатуры`, подчинён номенклатуре).

## 3. Архитектура обмена

Три локальных каталога на сервере (создать заранее):

- `C:\sync\tasks` — задания от приложения (1С читает и архивирует);
- `C:\sync\results` — результаты и выгрузка остатков от 1С (приложение читает);
- `C:\sync\archive` — обработанные задания.

Кодировка всех файлов — **UTF-8**. Разделитель полей — символ `|`.
Публикация файлов **атомарная**: сначала пишем `имя.part`, затем переименовываем в
`имя` (чтобы приёмник не прочитал полуфайл).

Точка входа обработки — процедура `ВыполнитьОбмен()` (экспортная в модуле объекта).
Запускается кнопкой формы и/или по расписанию (см. п. 10).

## 4. Протокол файлов

### 4.1 Задания: приложение → 1С

Приложение кладёт в `tasks` файлы `task_ГГГГММДДЧЧММСС.txt`. В файле одна или
несколько строк-команд:

| Команда (строка файла) | Действие 1С |
|---|---|
| `EXPORT_STOCK_ON_HAND` | Выгрузить остатки склада ЦС в файл `stock_*.txt` (каталог results). |
| `EXPORT_BARCODES` | Выгрузить полный справочник баркодов в файл `barcodes_*.txt` (каталог results). |
| `CREATE_MOVEMENT`\|`баркод`\|`склад_откуда`\|`склад_куда`\|`кол-во`\|`order_id`\|`площадка`\|`дата` | Создать и провести перемещение (резерв под заказ: ЦС → склад «в пути» площадки). |
| `CONFIRM_MOVEMENT`\|`баркод`\|`склад_откуда`\|`склад_куда`\|`кол-во`\|`order_id`\|`площадка`\|`дата` | Перемещение при подтверждении: склад «в пути» → склад площадки. |
| `CANCEL_MOVEMENT`\|`order_id`\|`площадка` | Реверс неподтверждённого заказа: склад «в пути» → ЦС. |

Восьмое поле `дата` (`ГГГГММДД`) — необязательное, дата документа перемещения;
пусто = текущая дата. Нужно для старта задним числом: уже состоявшиеся отгрузки
проводятся реальными датами заказов, иначе движения встали бы сегодняшним днём.

`order_id` сохраняется в реквизите `Комментарий` созданных документов в виде
`sync order_id=<order_id> <площадка>` — по нему ищутся движения для CANCEL.

Обработав файл, 1С **переносит его в `archive`** и пишет результаты (ниже).

### 4.2 Результаты по заданиям: 1С → приложение

По каждой команде с `order_id` (create/confirm/cancel) 1С пишет строку в файл
`result_ГГГГММДДЧЧММСС.txt` в каталог `results`:

```
order_id|OK|номер_документа_или_текст
order_id|ERROR|текст_ошибки
```

`EXPORT_STOCK_ON_HAND` строку-результат не требует — его ответ — файл остатков.

### 4.3 Выгрузка остатков: 1С → приложение

На команду `EXPORT_STOCK_ON_HAND` 1С пишет файл `stock_ГГГГММДДЧЧММСС.txt` в
`results`, по строке на позицию склада ЦС:

```
uid_1c|артикул|наименование|количество|баркод1,баркод2|размер|цвет
```

- `uid_1c` — `УникальныйИдентификатор()` характеристики (или номенклатуры, если
  характеристика не задана). Это ключ SKU на стороне приложения.
- `размер`, `цвет` — характеристика номенклатуры и реквизит цвета; приложение
  хранит их у товара и показывает в списках.
- `количество` — целое; **может быть отрицательным** (пересортица). Это не ошибка —
  приложение само отправит на площадки 0.
- Последнее поле — все баркоды позиции через запятую (минимум один; строки без
  баркодов пропускаются).

### 4.4 Выгрузка справочника баркодов: 1С → приложение

На команду `EXPORT_BARCODES` 1С пишет файл `barcodes_ГГГГММДДЧЧММСС.txt` в
`results`, по строке на КАЖДЫЙ баркод (в выгрузке остатков баркоды одного товара
перечислены через запятую — здесь наоборот):

```
uid_1c|артикул|наименование|баркод|размер|цвет
```

Выгрузка не зависит от остатков: в ней есть и позиции с нулём на складе. Нужна для
сопоставления товаров площадок с 1С — по полному справочнику оно работает даже там,
где каталог площадки ещё не догружен. Приложение запрашивает её раз в сутки, полный
разбор всего справочника — раз в неделю.

## 5. Соответствие метаданных базы

Обработка использует следующие объекты (сверено по конфигурации; при доработке —
проверять актуальность имён):

| Назначение | Объект / поля |
|---|---|
| Штрихкоды | `РегистрСведений.Штрихкоды`: измерение `Штрихкод`; реквизиты `Владелец` (= номенклатура), `ХарактеристикаНоменклатуры` (= характеристика). |
| Остатки | `РегистрНакопления.ТоварыНаСкладах`, виртуальная таблица `.Остатки(, Склад = &Склад)`: измерения `Склад`, `Номенклатура`, `ХарактеристикаНоменклатуры`; ресурс `Количество` (в запросе `КоличествоОстаток`). |
| Перемещение | `Документы.ПеремещениеТоваров`: реквизиты `СкладОтправитель`, `СкладПолучатель`, `МагазинОтправитель`, `МагазинПолучатель`, `Комментарий`; ТЧ `Товары` с полями `Номенклатура`, `Характеристика`, `Количество`. У документа **нет** реквизитов `Организация` и `ВидОперации`. |
| Склады | `Справочник.Склады`: поиск `НайтиПоНаименованию(Имя, Истина)`; реквизит `Магазин` (склад подчинён магазину — берётся для `Магазин*` документа). |
| Характеристики | `Справочник.ХарактеристикиНоменклатуры` (подчинён номенклатуре, поэтому UID характеристики уникален per SKU). |

## 6. Карта складов

Имена — **точно как в справочнике `Склады`** (обработка ищет по наименованию):

| Роль | WB | Ozon | Kit (Сайт AWER) |
|---|---|---|---|
| Источник (физический остаток) | `ЦС Склад` | `ЦС Склад` | `ЦС Склад` |
| «В пути» (резерв под заказ) | `Wildberries_Впути` | `OZON_Впути` | `AWER в пути` |
| Склад площадки (продано/отгружено) | `Wildberries_Склад_FBO` | `OZON_Склад` | `Сайт AWER` |

Имена складов приходят в файлах-заданиях; в 1С их достаточно найти по наименованию.
Магазин каждого документа заполняется из `Склад.Магазин`.

## 7. Логика обработки

`ВыполнитьОбмен()`:

1. `НайтиФайлы(КаталогTasks, "task_*.txt")` — перебор заданий.
2. По каждому файлу — `ОбработатьФайлЗадания`:
   - прочитать текст (`ЧтениеТекста`, UTF-8), разобрать построчно (`СтрРазделить`);
   - по каждой команде вызвать соответствующую операцию, накопить строки результата;
   - записать `result_*.txt` (если были команды с order_id) и/или `stock_*.txt`
     (если был EXPORT), атомарно;
   - переместить файл задания в `archive` (`ПереместитьФайл`).
3. Любая ошибка обработки файла пишется в журнал регистрации и не срывает разбор
   остальных файлов.

Операции:

- **`ВыполнитьПеремещение`** (CREATE/CONFIRM): находит номенклатуру+характеристику
  по баркоду, создаёт `ПеремещениеТоваров` (склады из имён, магазины из
  `Склад.Магазин`, order_id в комментарий), проводит, возвращает номер.
- **`ОтменитьПеремещенияЗаказа`** (CANCEL): находит проведённые перемещения по
  `Комментарий ПОДОБНО "%order_id=<id> %"`, создаёт обратные перемещения на ЦС.
- **`ВыгрузитьОстаткиЦС`** (EXPORT): запрос к `ТоварыНаСкладах.Остатки` по складу ЦС,
  формирует строки `uid|артикул|наименование|кол-во|баркоды`.

## 9. Задачи программиста 1С

1. Создать внешнюю обработку `ОбменССайтом`, в модуль объекта вставить готовый код.
2. Создать локальные каталоги `C:\sync\{tasks,results,archive}` (или согласовать
   другие пути и поправить `ПараметрыОбмена()`).
3. **Проверить проведение** `ПеремещениеТоваров` на тестовом задании: обязательные
   реквизиты, отсутствие блокирующих проверок (дата запрета редактирования, контроль
   остатков и т.п.). Если проведение требует доп. реквизитов — дозаполнить в
   `ВыполнитьПеремещение`.
4. Прогнать сквозной тест (см. п. ниже) и убедиться, что документы создаются, а
   `result_*.txt` формируется корректно.
5. Настроить **автозапуск** (п. 10).
6. Проверить корректную работу с **отрицательными остатками** (выгрузка не должна
   падать; отрицательные значения выгружаются как есть).

### Тест (приёмка)

1. В `C:\sync\tasks` положить `task_test.txt` (UTF-8):
   ```
   CREATE_MOVEMENT|<реальный баркод с остатком на ЦС Склад>|ЦС Склад|Wildberries_Впути|1|TEST-1|wb
   ```
2. Открыть `ОбменССайтом.epf` в 1С:Предприятии, нажать «Выполнить».
3. Ожидаемо: в `C:\sync\results` — `result_TEST-...txt` со строкой `TEST-1|OK|<номер>`;
   файл задания в `archive`; в базе — проведённый документ «Перемещение товаров»
   (ЦС Склад → Wildberries_Впути), комментарий `sync order_id=TEST-1 wb`.
4. Проверить EXPORT: задание с единственной строкой `EXPORT_STOCK_ON_HAND` → в
   `results` появляется `stock_*.txt` со строками остатков ЦС.

## 10. Автозапуск по расписанию

Обмен должен выполняться периодически (ориентир — раз в 1–2 минуты). Варианты:

- **Регламентное задание**, вызывающее обмен. Так как регламентные задания вызывают
  методы общих модулей, а не внешние обработки напрямую, потребуется тонкая обвязка:
  либо зарегистрировать обработку в подсистеме «Дополнительные отчёты и обработки»
  (в конфигурации есть `Справочник.ВнешниеОбработки` и
  `Перечисление.ВидыДополнительныхВнешнихОбработок`) — тогда в модуль объекта нужно
  добавить экспортную функцию `СведенияОВнешнейОбработке()` с командой-обработчиком и
  настроить расписание;
  либо встроить вызов `ВыполнитьОбмен()` в существующий механизм регламентных заданий
  базы.
- На боевом сервере обмен выполняется **на стороне сервера 1С** — сервер должен иметь
  доступ к каталогам `C:\sync` (при локальном размещении — доступ есть).

Реализацию автозапуска согласовать: подсистема «Дополнительные обработки» —
предпочтительный, штатный способ.

## 11. Эксплуатация и ограничения

- Все стороны обмена — на одной машине; каталоги локальные. При разнесении 1С и
  приложения на разные серверы канал нужно переводить на общий сетевой ресурс или FTP
  (тогда файловые операции заменяются на соответствующие).
- Обработка идемпотентна на уровне файлов: каждое задание обрабатывается один раз и
  уезжает в архив. Повторная обработка того же order_id со стороны приложения не
  ожидается (защиту от дублей держит приложение).
- Отрицательные остатки (пересортица) — штатная ситуация, выгружаются как есть.

## 12. На подтверждение / открытые вопросы

1. **Проведение `ПеремещениеТоваров`** — есть ли в базе блокирующие проверки
   (дата запрета редактирования, контроль отрицательных остатков, обязательные
   реквизиты помимо складов/товаров)? Проверяется на тестовом проведении.
2. **Автозапуск** — согласовать способ (Дополнительные обработки vs встроенный
   регламент).
3. **Пути каталогов** — `C:\sync\...` или иные (тогда поправить `ПараметрыОбмена()`).
