# Финансы площадок

Отдельная программа рядом с Sync Admin и «Репрайсером». Отчёты WB, Lamoda и
Яндекс KIT приводятся к единой форме. По ним считаются юнит-экономика и
дашборды по площадкам и делается сверка. Отчёты о продажах загружаются в 1С.

Своя база, свой вход, свои ключи площадок, своя служба Windows. Sync Admin
программа не трогает: его базу только читает, ради мэппинга баркодов и
принятых заказов.

## Откуда данные

| Площадка | Источник | Что это |
| --- | --- | --- |
| Wildberries | finance-api по токену с категорией «Финансы» | Официальные еженедельные отчёты реализации (тот же отчёт, что в кабинете) и их «Итого к оплате» |
| Wildberries | файл детализации из кабинета | То же, если API нет |
| Яндекс KIT | API заказов | Финансового отчёта у KIT нет. Продажи за период собираются из официальных данных заказов: доставлено минус отказы, стоимость доставки |
| Lamoda | почта (b2b@lamoda.ru) | Еженедельный отчёт: предварительные продажи по неделям |
| Lamoda | файл или письмо | Отчёт комиссионера, итоговый документ. Предварительные данные за его период заменяются им (коррекция) |
| любая | шаблон единой формы | Отчёт, который программа не умеет читать сама |

Себестоимость берётся из 1С (регистр «Себестоимость номенклатуры», в долларах)
и переводится в рубли по курсу ЦБ на дату продажи. Её можно задать и вручную
через Excel. Ручная цена приоритетнее, выгрузка из 1С её не перебивает.

## Страницы

- **Дашборд площадок**: выручка, к перечислению, прибыль по площадкам, динамика,
  лучшие и убыточные артикулы.
- **Отчёты площадок**: загрузка файлом, загрузка по API, журнал загрузок.
  На странице отчёта: сверка денег, сверка с заказами Sync Admin, товары без
  1С, отправка в 1С.
- **Сверка со сводом WB**: список отчётов WB (из API или файлом из кабинета)
  против загруженных. Видно, какие не загружены, у каких сходится и у каких
  расходится итог, по каким статьям.
- **Юнит-экономика**: по артикулу или SKU; комиссия, логистика, хранение,
  себестоимость, налог, прибыль, маржа, ROI.
- **Себестоимость**: Excel туда и обратно, запрос себестоимости из 1С; там же
  настройки расчёта (налог, доп. расходы, склады 1С, ручной курс).
- **API-ключи**: кабинеты, токены, кнопка «Проверить доступ», связь с кабинетом
  Sync Admin, почта для отчётов Lamoda.
- **Диагностика**: версия обработки 1С, справочник баркодов, задания 1С, фон,
  журнал действий.

## 1С

Обмен идёт той же обработкой «ОбменССайтом», но своими файлами: задания
`task_fin_*.txt`, ответы в `C:\sync\results\finance`. Протокол описан в
`1c/README.md`, раздел «Финансы площадок».

1. Обработку нужно обновить до **mark-4**: модуль `1c/ОбменССайтом_МодульОбъекта.txt`
   переносится в Конфигураторе, как обычно. Пока обработка не ответила на
   «Проверить обработку 1С» версией mark-4, программа не шлёт в 1С ничего.
2. По отчёту в 1С уходят **баркод, количество и сумма к перечислению продавцу**
   и только по кнопке «Отправить в 1С» на странице отчёта.
3. Баркод для 1С. Товар ищется по «Мэппингу» Sync Admin, затем по справочнику
   баркодов 1С. В 1С уходит баркод, прописанный у этого товара в самой 1С.
4. Еженедельные отчёты Lamoda в 1С не уходят: в них нет баркодов и возвратов.
   В 1С уходит отчёт комиссионера.

## Установка на сервер

Всё — PowerShell **от администратора**.

1. Скопировать на сервер пакет `mpfinance_finN.ps1` и запустить:
   `powershell -ExecutionPolicy Bypass -File <путь>\mpfinance_finN.ps1`.
   Он раскладывает файлы в `C:\mpfinance`.
2. Первая установка:
   `powershell -ExecutionPolicy Bypass -File C:\mpfinance\deploy\install_server.ps1`.
   Скрипт создаёт venv, `.env` со своими ключами, миграции, прогоняет тесты,
   заводит первого пользователя, ставит службу `mpfinance` на `127.0.0.1:8003`
   и ярлык «Финансы площадок».
3. Обновление: новый пакет, затем
   `powershell -ExecutionPolicy Bypass -File C:\mpfinance\deploy\update_server.ps1 -Tag finN`.
   По порядку: копия базы, миграции, тесты, перезапуск, проверка фона.

`MPFIN_SECRETS_KEY` из `C:\mpfinance\.env` — ключ шифрования токенов площадок.
Храните его отдельно от копий базы.

## Первый запуск: что проверить

1. «Диагностика» → «Проверить обработку 1С». Должен прийти ответ `mark-4`.
2. «API-ключи»:
   - завести кабинет WB, вписать токен с категорией «Финансы», нажать
     «Проверить доступ»;
   - связать кабинет с кабинетом Sync Admin;
   - то же для KIT;
   - кабинет Lamoda и почта: IMAP-сервер, адрес, пароль приложения.
3. «Себестоимость» → «Настройки»: склады 1С по площадкам. У Lamoda склад по
   умолчанию пустой, в базе он заведён как «Lamaoda_Склад».
4. «Отчёты площадок» → загрузка WB по API за 2–3 недели. Затем «Сверка со
   сводом WB»: итог строк должен сойтись с «Итого к оплате» WB.
5. Первый отчёт в 1С: открыть созданные документы, сверить с отчётом и только
   потом проводить. По умолчанию документы создаются непроведёнными.

## Что НЕ проверено на живом

- WB finance-api и заказы KIT на живых токенах. Методы и поля взяты из
  официальных спецификаций; первую загрузку нужно сверить с кабинетом.
- Документы продаж в 1С (`SALES_REPORT`): имена документов и реквизитов в
  модуле помечены `// НАСТРОИТЬ:` и с базой не сверены.
- Почта: проверена на поддельном IMAP-сервере. Нужен настоящий ящик, куда
  приходят письма b2b@lamoda.ru.

Разбор отчётов проверен на настоящих файлах:
- детализация WB №848966494 (читается целиком, статьи раскладываются по формуле WB);
- свод «Финансовые отчёты» WB (271 отчёт; формула «Итого к оплате» сходится
  до копейки);
- отчёт комиссионера Lamoda № CR000179664 за сентябрь 2026 (итог совпадает
  со строкой «Итого»);
- еженедельный отчёт Lamoda от 2026-10-05 (недельные суммы совпадают со
  сводкой отчёта).
