# Финансовый помощник — Telegram-бот

Учитывает расходы на бизнес, оплаченные с личных карт. В конце месяца по
выпискам показывает, сколько по каждой карте пришло и ушло, сколько из этого
на бизнес, а сколько на личное.

Отдельный проект, с Sync Admin не связан: свой код, своя база, своя служба.

## Как пользоваться

**В течение месяца.** Оплатили что-то для бизнеса с личной карты — пришлите
боту скриншот из банка или фото чека. Можно добавить подпись, например
«реклама ВК». Бот сам распознаёт сумму, дату, получателя, карту (по последним
цифрам или по банку) и статью расхода. Переспрашивает, только если чего-то
не хватает:

- не видно карту — кнопки с вашими картами;
- статья неочевидна — кнопки со статьями, предложенная отмечена ✓;
- покупка похожа на личную — «Бизнес / Личное»;
- оплата в валюте — сколько списано в рублях;
- та же сумма, дата и карта уже записаны — «повтор или другая оплата».

После записи под карточкой есть кнопки «Статья», «Карта», «Это личное»
и «Удалить» — ошибку можно исправить сразу. Несколько скриншотов подряд
встают в очередь, вопросы задаются по одному. Расход можно записать
и текстом: «3500 доставка СДЭК с Т-Банка вчера».

**Пачкой.** Скриншоты можно отправлять сразу пачкой: выделить в галерее
10, 30, 50 штук (Telegram отправит их альбомами) или прислать подряд.
- Бот ждёт 2–3 секунды тишины после последнего файла и разбирает всё разом.
  Одновременно распознаются до 4 файлов, поэтому пачка идёт в несколько раз
  быстрее, чем по одному.
- Сразу приходит «⏳ Принял N файлов, разбираю — примерно M мин», затем
  одна сводка:
  ```
  📥 Разобрал 8 файлов.
  🔁 Повторы (уже записаны или в этой же пачке): 2
  🚫 Не похоже на оплату: 1
  ✅ Записано как бизнес: 3 на 7 000,00 ₽
    • Логистика и доставка: 1 000,00 ₽
    …
  №2 20.09  1 000,00 ₽  Сбер  бизнес · Логистика и доставка · СДЭК
  …
  ❓ Вопрос 1 из 2
  3 000,00 ₽ · 20.09 · …  С какой карты оплачено?
  ```
- Всё, что понятно без вопросов, записывается сразу. Вопросы идут в конце,
  по одному, с номером «Вопрос 1 из N».
- Переводы между своими счетами, поступления и повторы видны в той же сводке.
- Один сбойный файл не ломает пачку: он попадает в «Не распознано», его
  можно прислать ещё раз.
- В режиме сверки пачка страниц выписки (или скриншотов «Истории») тоже
  разбирается параллельно, и итог по ним приходит одним сообщением.
- Если сразу после файлов отправить команду или нажать кнопку, бот сначала
  дообработает пачку, а потом выполнит команду.

**В конце месяца — сверка.**

1. `/sverka` → выбрать месяц → выбрать карту.
2. Прислать выписку по этой карте: PDF, скриншоты, Excel или CSV, можно
   несколькими сообщениями. Если выписки нет, достаточно написать
   «пришло 120000, ушло 95000».
3. `/done` — бот покажет итог по карте:
   - **Пришло** и **Ушло** — по выписке;
   - **на бизнес** — сумма ваших записей по этой карте;
   - **на личное** — всё остальное, что ушло, без переводов между своими
     картами;
   - ⚠️ записи, которых нет в выписке (обычно выбрана не та карта);
   - списания, которые сейчас считаются личными. Если среди них есть бизнес
     (забыли прислать скриншот), отправьте `/biz 12 15`, и они станут
     бизнес-расходами.
4. Повторить для остальных карт.
5. `/itog` — общий свод: по каждой карте пришло/ушло/бизнес/личное и два
   итога:
   - **💼 Ушло на бизнес** с разбивкой по статьям;
   - **🏠 Личные расходы**. Если по какой-то личной карте нет выписки, бот
     предупредит, что её личные расходы в итог не вошли.

   К своду прикладывается Excel-файл: лист «Свод», все бизнес-расходы
   с путями к скриншотам и лист расхождений.

Поступления на карты бот не записывает, они видны в выписке в «Пришло».

## Статьи расходов: привязка получателей

Если вы выбрали статью для расхода (на вопрос бота или кнопкой «Статья» у
записи), бот запоминает правило **«получатель → статья»**. Следующие расходы
этого получателя сразу попадают в эту статью, без вопроса и без догадок
модели. «ООО „СДЭК-Глобал“» и «сдэк глобал» считаются одним получателем.

- Меняете статью у записи — правило обновляется, и бот предлагает одной
  кнопкой перенести в новую статью все прошлые записи этого получателя.
- Правила применяются и к строкам выписки: предложенная статья берётся
  из правила.
- `/rules` — все правила по статьям, `/delrule 3` — удалить правило.
- Слишком общие имена (например, просто «ИП») правилом не становятся.

## Сводная таблица за период

`/svod` предлагает кнопки «Эта / прошлая неделя», «Этот / прошлый месяц»
и «Этот год». Свой период задаётся датами: `/svod 01.09.2026-15.09.2026`,
месяц — `/svod 2026-03`, год — `/svod 2026`.

В чат приходит раскладка бизнес-расходов:

```
💼 Всего: 19 200,00 ₽ (5 операций)

▪️ Реклама и продвижение: 12 000,00 ₽ · 62%
    Яндекс Директ: 12 000,00 ₽
▪️ Логистика и доставка: 4 200,00 ₽ · 22%
    СДЭК: 3 500,00 ₽
    Деловые Линии: 700,00 ₽
▪️ Без статьи: 3 000,00 ₽ · 16%
    Петров П. П.: 3 000,00 ₽

По неделям:
  31.08–06.09: 1 000,00 ₽
  …
```

К раскладке прикладывается Excel:
- **Сводная** — статьи × дни (для недели), недели (до двух месяцев) или
  месяцы (дольше), с итогами и долей каждой статьи;
- **Раскладка** — статья → получатели: сумма и число операций;
- **Данные** — все операции таблицей Excel с фильтрами в заголовках
  (по дате, неделе, месяцу, статье, получателю, карте);
- **Фильтр по датам** — поменяйте даты «С» и «По», и суммы по статьям
  пересчитаются формулами.

В сводную входят записанные бизнес-расходы и списания с бизнес-счёта по
выпискам, которые ещё не разнесены по статьям («Без статьи»). Личные расходы
считаются только помесячно по выпискам, их показывает `/itog`.

## Защита от повторов

| Что повторилось | Что делает бот |
|---|---|
| Тот же скриншот ещё раз (в том числе пересланный: Telegram может пережать картинку, но id файла тот же) | сразу отвечает «уже присылали» и показывает запись; в Claude заново не отправляет |
| Тот же скриншот, пока по первому ещё идёт вопрос | «уже в работе» |
| Другой скриншот той же оплаты: сумма та же, дата ±1 день, та же карта **или** тот же получатель | спрашивает «Повтор / Нет, это другая оплата» |
| Скриншот второй стороны перевода (было списание, теперь зачисление) | дополняет уже записанный перевод, новый не создаёт |
| Похожий перевод с **той же** стороны | спрашивает: это повтор или второй перевод на ту же сумму |
| Тот же файл выписки по той же карте | «уже загружен», в Claude не отправляет |
| Тот же файл выписки по другой карте | загружает, но предупреждает: проверьте, та ли карта |
| Другой файл с теми же строками выписки (скриншот той же страницы) | строки не задваиваются; две одинаковые покупки в одном файле сохраняются обе |

Если удалить запись, тот же скриншот можно прислать заново, и он запишется.
После «Загрузить заново» в сверке можно снова прислать тот же файл выписки.

## Переводы между своими счетами

Перевели деньги с одной своей карты на другую (или с бизнес-счёта себе)?
Пришлите скриншот, как и расход. Бот поймёт, что это перемещение, и запишет
его как **«откуда → куда»**, например `П3 · 100 000 ₽ · Россия → ВТБ`. Если
второй счёт на скриншоте не виден, бот спросит его кнопками. Среди кнопок
есть «Другой мой счёт», если этот счёт в боте не ведётся.

При сверке перевод вычитается у обеих карт: из «Пришло» у той, куда пришли
деньги, и из «Ушло» у той, откуда ушли. Поэтому в свод идёт **приход без
переводов**, а личные траты не завышаются на сумму перевода:

```
Пришло: 439 000,00 ₽
  − переводы со своих счетов: 100 000,00 ₽
  = приход без переводов: 339 000,00 ₽
Ушло:   615 736,05 ₽
  − переводы на свои счета: 50 000,00 ₽
  на бизнес: 15 417,00 ₽
  на личное: 550 319,05 ₽
```

- Это особенно важно для ВТБ: по экрану «История» есть только общие итоги
  месяца, и увидеть переводы в них бот может только по вашим скриншотам.
- Если вы прислали скриншоты обеих сторон одного перевода (списание и
  зачисление), бот запишет его один раз.
- Если в выписке с операциями перевод уже помечен как «свой», а вы его
  тоже записали, он вычитается один раз. Если записанный перевод в выписке
  не найден, бот предупредит, но всё равно его вычтет.
- Исправить перевод: `/fix П3`, затем кнопки «Откуда», «Куда», «Удалить».
  Все переводы месяца есть в `/list`.
- Скриншоты во время сверки (после `/sverka` и до `/done`) бот считает
  частью выписки. Переводы присылайте вне сверки.

Запись из выписки и запись со скриншота считаются одной операцией, если сумма
совпадает до копейки, а даты расходятся не больше чем на 3 дня. Повторно
присланный кусок выписки не задваивается.

Прочие команды: `/list 2026-02` — записи за месяц, `/fix 42` — исправить запись
(`/fix П3` — перевод), `/cards`, `/addcard Сбер 1234 Сбер`,
`/delcard 2`, `/cats`, `/addcat Обучение`, `/cancel`, `/help`.

## Старт задним числом (например, с 1 января)

Скриншотов за прошлые месяцы обычно нет, зато есть выписки. Порядок такой:

1. Добавьте три карты (`/addcard …`).
2. Скачайте в каждом банке одну выписку по карте за весь период,
   с 1 января по сегодня: PDF или Excel.
3. `/sverka` → «📚 Выписка за несколько месяцев» → карта → пришлите файл →
   `/done`. Операции сами разложатся по месяцам. Бот покажет итоги по каждому
   месяцу и список списаний, **похожих на бизнес** (СДЭК, рекламные кабинеты,
   сервисы маркетплейсов, поставщики…), с предложенной статьёй.
4. Проверьте список: лишнее уберите `/notbiz 12 15`, затем нажмите
   «✅ Записать все как бизнес». Бот запишет их одной сводкой, без вопросов
   по каждому.
5. Бизнес-расходы, которые бот не распознал, найдите через
   `/vypiska 2026-03` (все списания месяца, которые сейчас считаются личными)
   и добавьте `/biz 7 9`. Статью бот спросит, если не сможет её угадать.
6. Повторите для остальных карт и получите свод: `/itog 2026` — с января
   по текущий месяц: бизнес и личное по месяцам, итог бизнеса по статьям
   и итог личных расходов.

Если за прошлые месяцы всё-таки есть скриншоты, просто пришлите их. Дата
берётся со скриншота, файл попадает в папку месяца оплаты.

Кнопками в `/sverka` можно выбрать любой из последних 12 месяцев. Более
ранний месяц задаётся вручную: `/sverka 2025-06`.

Не присылайте две выписки с пересекающимися датами по одной карте. Одинаковые
строки бот не задвоит, но банк может по-разному написать описание одной и той
же операции в двух файлах, и тогда она посчитается дважды. Чтобы перезагрузить
месяц, выберите его в `/sverka` и нажмите «Загрузить заново».

## Особенности банков (по реальным образцам)

**Номера карт.** В квитанциях часто стоит номер счёта, а не карты: у банка
«Россия» это «Счет списания 4081…9012», у ВТБ — «Мастер-счет •5678», хотя
в другой квитанции той же карты будет «Карта для жизни •1234». Поэтому у карты
в боте может быть несколько номеров. Если бот видит незнакомый номер, он один
раз спросит, какая это карта, и запомнит ответ. Номера можно задать и сразу:
`/addcard ВТБ 1234 5678 ВТБ`. Если на скриншоте номера нет, карта определяется
по банку, в том числе по названию приложения: «ABR Direct» — это банк «Россия».

**Категории банка не учитываются.** Подписи вроде «Развлечения» или «Услуги»
банк ставит автоматически, поэтому бот на них не опирается. Статью он
предлагает сам, а если сомневается, спрашивает.

**Банк «Россия», выписка «Список операций».** Получатель в ней не указан,
у всех оплат одно описание «Оплата по QR-коду через СБП». Поэтому:
- предложений «похоже на бизнес» по такой выписке почти не будет;
- операции различаются по дате, **времени** и сумме, и бот показывает время
  в списках `/vypiska` и после `/done`;
- **для старта задним числом** удобнее открыть в ABR Direct «Историю операций»
  и прислать боту квитанции нужных бизнес-платежей. Бот запишет их с их
  датами, а при сверке они сами сопоставятся с выпиской.

Комиссию, которая идёт внутри операции отдельной суммой («Комиссия −110 ₽»),
бот записывает отдельным списанием, чтобы итог «ушло» сошёлся.

**ВТБ, экран «История».** Верхние плашки «Расходы в сентябре» и «Поступления
в сентябре» — это готовые итоги месяца. Скриншот этого экрана можно прислать
в `/sverka` вместо выписки или вместе с ней. Если прислать его вне сверки, бот
подскажет открыть `/sverka`. Учтите, что ВТБ считает эти итоги по всем своим
картам и счетам сразу.

## Два пользователя: у каждого свои данные

Бот рассчитан на двух (и больше) людей со своими деньгами:
- **Вход** по своему аккаунту Telegram. Бот узнаёт человека по Telegram id,
  пароль не нужен: вход подтверждает сам Telegram. Чужой id получает только
  «Доступ закрыт».
- **Отдельная база у каждого**: `data/users/<telegram id>/finance.db`, рядом
  свои скриншоты. Карты, статьи, правила «получатель → статья», записи,
  переводы, выписки, `/itog`, `/svod` и Excel у каждого свои. Это не фильтр
  в запросах, а разные файлы, поэтому ошибка в каком-то запросе не может
  показать чужие данные.
- Данные выбираются по тому, **кто** написал или нажал кнопку. Переслать
  сообщение с кнопками другому человеку бесполезно: его нажатие сработает
  только на его собственные данные.
- Папки пользователей закрыты правами (700). Бэкап сохраняет базу каждого
  пользователя отдельным файлом.
- Долгий разбор пачки у одного пользователя не задерживает другого.
- Если бот уже работал с одной общей базой (`data/finance.db`), при первом
  запуске она переезжает к **первому** id из `ALLOWED_USER_IDS`. Второй
  пользователь начинает с чистой базы.
- Бот работает только в личном чате. Добавить его в общую группу нельзя,
  там он молчит.

## Бизнес-счёт (расчётный счёт ИП с бизнес-картой)

Добавляется с пометкой `бизнес`: `/addcard ПСБ 4987 ПСБ бизнес`.

| Операция | Как учитывается |
|---|---|
| Оплата с бизнес-счёта или бизнес-карты (платёжка «СКБ Контур» и т. п.) | ушло на бизнес, по статье |
| Перевод с бизнес-счёта другому человеку (СБП B2C) | ушло на бизнес; бот спросит статью (обычно «Подрядчики и зарплата») |
| Перевод с бизнес-счёта **вам** | перевод между своими счетами: не расход, вычитается из «ушло» бизнес-счёта и из «пришло» вашей карты |
| Покупка, которую вы пометили как личную | личные расходы |
| Поступления (кэшбэк, выплаты маркетплейсов) | не записываются, в сверке видны как «пришло» |

В платёжном поручении бот берёт счёт **плательщика**, а не получателя и не
корреспондентский. По счёту 40802… он понимает, что платёж сделан с бизнес-счёта.
Если бизнес-счёт один, бот выберет его сам и запомнит номер.

Сверка по бизнес-счёту (`/sverka` → ПСБ) показывает пришло/ушло и сколько из
ушедшего переведено вам. Всё остальное, что ушло с бизнес-счёта, сразу входит
в «Ушло на бизнес». То, что ещё не разнесено по статьям, попадает в строку
«Без статьи». Кнопка «Разнести по статьям» запишет эти списания по статьям,
которые предложил Claude, а нераспознанные — в «Прочее».

## Установка на сервер

Пошагово, для первой установки и обновления: **[УСТАНОВКА.md](УСТАНОВКА.md)**.
Коротко:

```bash
unzip finance-bot.zip && cd finance_assistant
sudo bash deploy/install.sh     # установка и обновление; данные и .env не трогает
sudo bash /opt/finance-bot/deploy/setup.sh --public   # страница: ключ, токен, id → бот запущен
```

Скрипт `deploy/install.sh` делает всё сам:
- создаёт пользователя службы и ставит код в `/opt/finance-bot`;
- создаёт виртуальное окружение с зависимостями;
- кладёт шаблон `.env`, выставляет права (код — root, данные — только служба);
- ставит службу `finance-bot` и ежедневный бэкап `finance-bot-backup.timer`;
- при обновлении перед заменой кода делает бэкап баз;
- после запуска проверяет, что служба жива, а если нет — показывает журнал.

**Страница настройки** (`deploy/setup.sh`) — временная веб-страница для ключа
Claude API, токена бота и Telegram id обоих пользователей:
- ссылка одноразовая, страница закрывается после сохранения или через 15 минут,
  а после 20 неверных адресов — сразу;
- по умолчанию доступна только на сервере (через SSH-туннель), с `--public` —
  по HTTPS с временным сертификатом; порт в ufw открывается только на это время;
- ключи на странице целиком не показываются, пустое поле — «не менять»;
- токен и ключ проверяются живым запросом, после сохранения бот перезапускается;
- кнопка «Кто писал боту» находит id тех, кто написал боту, пока он не запущен.

Бот сам опрашивает Telegram, поэтому ни домен, ни открытый порт ему не нужны.
Запустить его можно на любой машине с интернетом, в том числе на VPS
Sync Admin.

**Бэкап:** всё хранится в `FINANCE_DATA_DIR`: база `finance.db` и скриншоты
в `receipts/ГГГГ-ММ/`. Таймер `finance-bot-backup.timer` каждый день в 03:30
кладёт копию в `/var/backups/finance-bot` и хранит 30 дней. Базу он копирует
средствами SQLite: простое копирование файла во время записи может испортить
копию. Сделать копию вручную: `sudo systemctl start finance-bot-backup`.
Восстановить: остановить бота, положить копию на место `data/finance.db`
и запустить бота.

Служба ограничена: писать она может только в `data/`, файлы создаёт с правами
«только владелец», работает только в личном чате с ботом.

## Безопасность и данные

- У каждого пользователя своя база, чужие данные ему недоступны (см. «Два пользователя»).
- Бот отвечает только пользователям из `ALLOWED_USER_IDS`. Остальным он
  сообщает только их собственный id.
- Скриншоты и выписки отправляются на распознавание в Claude API (Anthropic).
  В Telegram они тоже проходят через серверы Telegram. Номера карт целиком
  не нужны: боту хватает последних 4 цифр.

## Разработка

```bash
cd finance_assistant
python3 -m venv venv && venv/bin/pip install -r requirements.txt pytest
venv/bin/python -m pytest -q
```

Тесты подменяют Claude фейковым распознавателем и Telegram не используют.

- `finance/flow.py` — весь сценарий диалога (вопросы, кнопки, сверка), без Telegram;
- `finance/bot.py` — обвязка python-telegram-bot;
- `finance/recognize.py` — запросы к Claude: скриншот → платёж, выписка → операции;
- `finance/reconcile.py` — сопоставление с выпиской и месячный свод;
- `finance/report.py` — тексты и Excel;
- `finance/storage.py` — SQLite.

## Что не проверено

- Распознавание на настоящих скриншотах и выписках: в среде разработки не было
  ключа Claude API. Проверено только, что запрос правильно формируется
  и ответ правильно разбирается. Первые скриншоты стоит проверить глазами.
- Насколько точно модель отбирает «похожие на бизнес» списания в выписке.
  Это только предложение: список нужно проверить перед нажатием кнопки.
- Работа бота с настоящим Telegram: не было токена. Логика диалога покрыта
  тестами, а подключение к Telegram собрано по документации python-telegram-bot 22.
