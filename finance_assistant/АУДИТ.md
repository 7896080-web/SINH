# Аудит помощника по финансам (сентябрь 2026)

## Как проводился

- Три независимых проверяющих, у каждого своя зона:
  1. точность расчётов (сверка, свод, сводная);
  2. диалог и состояние (очередь, кнопки, режимы);
  3. хранилище, распознавание, Telegram, развёртывание.
- Каждую находку проверяющий **воспроизвёл кодом** на настоящих классах
  `Flow`/`Storage` с подменой Claude. Перед исправлением находки перепроверялись.
- На каждое исправление добавлен регрессионный тест: `tests/test_audit_*.py`
  и дополнения в других тестах. Было 87 тестов, стало **138**, все проходят.
- После исправлений исходные сценарии проверяющих прогнаны заново. Они дают
  правильный результат или отказ «вопрос неактуален».

**Не проверено вживую:** распознавание Claude на настоящих скриншотах и
выписках, работа с настоящим Telegram (не было ключа API и токена бота).
Это главный оставшийся риск, см. раздел «Слабые места».

## Как устроено и как блоки влияют друг на друга

```
Telegram (bot.py) ──► Диалог (flow.py) ──► Распознавание (recognize.py → Claude API)
   личный чат,          очередь операций,        скриншот → операция,
   доступ по id,        вопросы и кнопки,        выписка → строки
   файлы, ожидание      сверка, правила,
                        защита от повторов
                              │
                              ▼
                        Хранилище (storage.py, SQLite)
                        карты · статьи · расходы · переводы · выписки ·
                        правила «получатель → статья» · отпечатки файлов ·
                        состояние чата
                              │
                              ▼
                        Сверка (reconcile.py) ──► Отчёты (report.py: /itog, Excel)
                        сопоставление записей        Сводная (pivot.py: /svod)
                        со строками выписок
```

**Главные цепочки причин и следствий:**

1. **Скриншот → статья.** Claude определяет получателя, затем проверяется
   правило «получатель → статья». Если его нет, берётся статья от Claude, а при
   сомнении бот спрашивает. Выбор пользователя создаёт правило. **Следствие:**
   одно неверное правило тихо портит все будущие записи этого получателя.
   Поэтому правила не создаются из безликих описаний и из записей, взятых
   из выписки, и в карточке видна пометка «📌 по правилу».
2. **Скриншот → карта.** Номер на скриншоте часто номер счёта, а не карты.
   Незнакомый номер вызывает вопрос о карте и запоминается за ней. **Следствие:**
   ошибка в выборе карты переносит расход в чужую карту. Это видно в сверке как
   «записано, но не найдено в выписке».
3. **Запись ↔ выписка.** Сопоставление идёт по сумме (точно) и дате (±3 дня)
   по всей карте, через границы месяцев. Сопоставленная запись относится
   к месяцу строки банка. **Следствие:** от сопоставления зависят «личное»
   (остаток), «Без статьи» на бизнес-счёте, предложения «похоже на бизнес»
   и вычет переводов. Ошибка здесь бьёт по всем итогам сразу, поэтому этот
   блок проверен сильнее всего.
4. **Перевод между своими счетами.** Он вычитается из «пришло» у получателя
   и из «ушло» у отправителя. **Следствие:** если перевод не записан, а
   в выписке только итоги (ВТБ «История»), личные расходы будут завышены
   на его сумму.
5. **`/itog` и `/svod`.** Оба строятся из одного месячного свода, поэтому
   бизнес за месяц в них совпадает по построению. Это закреплено тестами.

## Слабые места, которые остаются

По убыванию важности. Это не ошибки кода, а ограничения подхода или данных,
которые стоит знать.

1. **Распознавание не проверено на реальных данных.** Точность чтения сумм,
   дат, номеров, получателей, а также разбор длинных PDF-выписок известны
   только по документации. Все тесты подменяют Claude. **Что делать:** первые
   2–3 недели сверять каждую карточку «✅ Записано» глазами, первую выписку
   по каждой карте сверить с итогами банка.
2. **Строки выписки склеиваются по точному совпадению** даты, времени, суммы
   и описания. Если банк в двух пересекающихся файлах опишет операцию
   по-разному или модель прочитает описание иначе, строка задвоится.
   **Что делать:** не присылать пересекающиеся выписки по одной карте,
   а для перезагрузки месяца использовать «Загрузить заново».
3. **Сопоставление: сумма точно, дата ±3 дня.** Не сработает для частичного
   возврата, холда с другой суммой, оплаты в валюте (сумма в рублях
   отличается) и проводки позже 3 дней. Такие записи попадут в «не найдено
   в выписке», а строки — в «личное». Бот предупреждает, но исправлять
   придётся вручную.
4. **Личные расходы считаются только помесячно и только по картам
   с выпиской.** По неделям их не посчитать (в `/svod` только бизнес).
   Без выписки по карте личное по ней неизвестно, и итог это явно отмечает.
5. **Итоги ВТБ «История» — по всем счетам ВТБ сразу.** Переводы между счетами
   внутри ВТБ бот в них не видит. Их нужно записывать скриншотами, иначе
   личное будет завышено.
6. **Выписка банка «Россия» без получателей.** Предложений «похоже на бизнес»
   по ней почти не будет. Бизнес-расходы нужно присылать квитанциями.
7. **Валюта в выписках не учитывается.** Строки считаются рублёвыми.
8. **Правило важнее Claude.** Если правило ошибочно, оно будет срабатывать,
   пока его не поменяют. Видно по пометке 📌. Исправляется сменой статьи
   у любой записи (бот предложит поправить и прошлые) или `/delrule`.
9. **Сообщения обрабатываются по одному.** Пока идёт разбор длинной выписки,
   остальные сообщения ждут. Для одного-двух пользователей это приемлемо.
   Распараллеливание потребует блокировок на уровне чата и отдельных
   соединений с базой.
10. **Общие данные для всех разрешённых пользователей.** Карты, записи
    и правила общие, раздельно только состояние диалога. Для семьи это
    удобно, для разных людей с разными деньгами — нет.
11. **Бэкап лежит на том же сервере.** От поломки диска не спасёт. Нужна
    копия вне сервера, например ежедневная выгрузка в облако.
12. **`flow.py` крупный (около 1 300 строк).** Логика держится на тестах.
    Если бот будет развиваться дальше, стоит разделить его на части
    (операции, сверка, отчёты, справочники).

## Чек-лист первого живого запуска

1. `/addcard` для всех карт, для бизнес-счёта — с пометкой `бизнес`.
2. Три-пять разных скриншотов по каждой карте. Проверить сумму, дату, карту,
   статью и запомненные номера (`/cards`).
3. Скриншот перевода между своими картами: запись «откуда → куда».
4. `/sverka` по одной карте за прошлый месяц. Сравнить «Пришло/Ушло» с итогами
   в приложении банка, проверить списки «не найдено» и «похоже на бизнес».
5. `/itog` и `/svod` за тот же месяц: бизнес должен совпадать.
6. `sudo systemctl start finance-bot-backup` и проверить, что копия появилась.
