# Установка на рабочий компьютер — инструкция для Claude на этом компьютере

Ты — Claude на **рабочем компьютере с КриптоПро**. Программа «Маркировка и
поставки» ставится сюда, а с сервером 1С её связывает только SFTP к папкам
`C:\sync` (ТЗ, разд. 2 и 9.1). Твоя задача — поставить программу, проверить
всё, что проверяется отсюда, и **остановиться** там, где нужен человек или
сервер. Сервер ты не настраиваешь: у тебя нет к нему административного
доступа, и не должно быть.

Консоль Windows — PowerShell 5.1. Файлы `.ps1` запускай **файлом**
(`powershell -ExecutionPolicy Bypass -File …`), а не вставкой. Журналы
программы читай с `-Encoding UTF8`.

## Нельзя — ни при каких обстоятельствах

1. **Показывать, копировать, отправлять закрытые ключи и секреты**:
   `C:\marking\ssh\id_ed25519` (без `.pub`), `C:\marking\.env` целиком,
   `MARKING_SECRETS_KEY`, API-ключ Нацкаталога, PIN токена, экспорт
   сертификатов с закрытым ключом. Открытая часть `id_ed25519.pub` — можно,
   она для сервера.
2. **Принимать ключ сервера вслепую.** `known_hosts` создаёт установщик, но
   отпечаток сверяет ЧЕЛОВЕК с тем, что показывает сервер (`SFTP_1C.md`,
   шаг 5). Не совпало — удалить `known_hosts` и остановиться.
3. **Класть файлы в `C:\sync` сервера руками** (через `sftp` или иначе), кроме
   проверки `ls`. Любой `task_*.txt` там 1С исполняет: перемещение товара —
   это документ, который не отменить.
4. **Писать в базу программы в обход неё** (`sqlite3 … UPDATE/DELETE`).
5. **Трогать sync_admin** в любом виде.

## Шаг 0. Файлы программы

Нужно содержимое каталога `marking/` репозитория `7896080-web/sinh`, ветка
`claude/magical-keller-i9x52y`, в `C:\marking` (должно получиться
`C:\marking\markapp\main.py`). Если есть git и доступ к репозиторию:

git clone --depth 1 -b claude/magical-keller-i9x52y https://github.com/7896080-web/sinh C:\marking_src
robocopy C:\marking_src\marking C:\marking /E

Иначе файлы приносит человек. `C:\marking_src` после копирования не нужен.

## Шаг 1. Предварительная проверка — только смотрит

```powershell
powershell -ExecutionPolicy Bypass -File C:\marking\deploy\check_workstation.ps1 -Server 136.243.92.95
```
Разбери вывод и доложи человеку коротко, по пунктам:
- Python 3.11+ — есть? Нет — попроси человека поставить с python.org с
  галочкой «Add python.exe to PATH» (установщик тебе нельзя запускать с
  правами администратора без его согласия).
- клиент OpenSSH — есть?
- КриптоПро CSP и **срок лицензии** (в ТЗ это открытый вопрос: однажды
  истекала);
- сертификаты с ИНН: чьи, до какого числа, есть ли закрытый ключ. Должен
  быть сертификат ИП Яворской, ИНН **910223073620**;
- сервер `136.243.92.95:443` — доступен?
- **True API** — ожидается ответ 200;
- **СУЗ ping** — ожидается 401 или 400: доступ с этой машины подтверждён
  заказчиком 29.09.2026 (отсюда заказывали коды). 451 — значит, изменилась
  сеть; остановись и скажи человеку.

## Шаг 2. Установка

```powershell
powershell -ExecutionPolicy Bypass -File C:\marking\deploy\install_workstation.ps1 -Server 136.243.92.95
```
Добавь `-Autostart`, если человек хочет запуск при входе в Windows.
По ходу установщик:
- печатает строку `ssh-ed25519 …` — **передай её человеку** для сервера
  (`SFTP_1C.md`, шаг 4);
- печатает отпечаток ключа сервера `SHA256:…` — **передай человеку** для
  сверки (`SFTP_1C.md`, шаг 5) и жди его ответа «совпало»;
- спрашивает логин и пароль первого пользователя — их вводит человек, не
  ты: не придумывай пароль и не проси его прислать в чат;
- напоминает унести `MARKING_SECRETS_KEY` в хранилище паролей. Покажи
  человеку, ГДЕ он лежит (`C:\marking\.env`), но не выводи его значение.

Тесты внутри установщика должны быть зелёными (один тест пропускается —
проверка модуля 1С, его рядом нет; это нормально). Красные — остановись и
покажи вывод.

## Шаг 3. Ждать человека: сервер

Человек на сервере ставит OpenSSH Server (если его нет) и запускает
`server_sftp_setup.ps1 -PublicKey "<строка из id_ed25519.pub>"`
(`SFTP_1C.md`, «Коротко»), затем сверяет отпечаток (шаг 5). Не продолжай, пока он не скажет, что готово и отпечаток
совпал.

## Шаг 4. Проверка SFTP — только чтение

```powershell
sftp -P 443 -i C:\marking\ssh\id_ed25519 -o UserKnownHostsFile=C:\marking\ssh\known_hosts -o StrictHostKeyChecking=yes marking_sftp@136.243.92.95
```
В `sftp>` только `ls` (ожидается `tasks`, `results`, `archive` и прочее
содержимое `C:\sync`), потом `bye`. Никаких `put`, `rm`, `rename`.

Проверка, что лишнего не открыто: `ssh -p 443 -i C:\marking\ssh\id_ed25519
marking_sftp@136.243.92.95` должен сразу закрыться («only sftp»). Если
открылась командная строка — **немедленно выйти** и сказать человеку: сервер
настроен не по инструкции.

## Шаг 5. Запуск и PING

Запуск — ярлыком «Маркировка» или:
```powershell
powershell -ExecutionPolicy Bypass -File C:\marking\deploy\run_marking.ps1
```
Проверка, что программа жива: `Invoke-WebRequest http://127.0.0.1:8001/health -UseBasicParsing`
— `{"ok":true,…}`.

PING в 1С отправляет **человек** в браузере: «Диагностика» → «Отправить
PING». Ответ придёт, когда 1С обработает задание по расписанию, и только если
обработка 1С уже обновлена (`C:\marking\1c\ОБНОВЛЕНИЕ_ОБРАБОТКИ.md` — это
делает человек в Конфигураторе, на копии базы сначала). Старая обработка на
PING молчит — это не поломка SFTP.

Если на «Диагностике» ошибка обмена — читай её текст и
`C:\marking\logs\marking.err.log` (`Get-Content … -Encoding UTF8 -Tail 50`).
Типовые: «нет файла ключей сервера» (шаг 2 не дошёл до сервера), «КЛЮЧ
СЕРВЕРА ИЗМЕНИЛСЯ» (не правь `known_hosts` сам — скажи человеку),
«недоступен» (сеть).

## Шаг 6. Плагин КриптоПро

Проверять — с адреса программы, не файлом: доверие плагина зависит от
адреса страницы. Человек в программе открывает «Диагностика» → «Проверить
плагин КриптоПро» (`http://127.0.0.1:8001/diagnostics/plugin-check`) и смотрит: видны ли сертификаты с ИНН,
проходит ли пробная подпись. Результат запиши в отчёт — это открытый вопрос
ТЗ (п. 10.2).
