# Установка и обновление программы «Маркировка и поставки»

**Порядок развёртывания целиком — что и на какой машине — `РАЗВЁРТЫВАНИЕ.md`.**
Ниже — подробности по рабочему компьютеру.

**Основной вариант (с 29.09.2026) — рабочий компьютер с КриптоПро.** Программа
стоит там, где подпись и сертификаты, и ходит в Честный знак напрямую (вход
в ЧЗ сертификатом — со страницы организации; вживую с ЧЗ ещё не проверено). С
сервером её связывает только 1С: файлы заданий и ответов идут по SFTP на
порт 443 до `C:\sync` сервера (`SFTP_1C.md`). Служб нет — программа
запускается ярлыком «Маркировка» и работает, пока открыта; к 1С обращается
только когда есть задание.

## Первая установка (рабочий компьютер)

1. **Python 3.11+** с python.org, галочка «Add python.exe to PATH».
2. **Файлы.** Создайте `C:\marking` и скопируйте туда содержимое каталога
   `marking/` репозитория (`C:\marking\markapp\main.py`,
   `C:\marking\deploy\install_workstation.ps1` и т. д.).
3. **Установка** (обычный PowerShell, права администратора не нужны):
   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\marking\deploy\install_workstation.ps1 -Server 136.243.92.95
   ```
   С `-Autostart` программа будет запускаться при входе в Windows.
   Скрипт создаёт venv и `.env` со своими секретами, ключ SFTP, записывает
   ключ сервера, прогоняет миграции и тесты, заводит первого пользователя и
   кладёт ярлык «Маркировка» на рабочий стол.
4. **Сервер** — OpenSSH Server и `server_sftp_setup.ps1` с открытым ключом из
   вывода установщика (`SFTP_1C.md`, «Коротко»). Затем **ещё раз** запустить
   установщик: он запишет ключ сервера и напечатает отпечаток — сверить с
   тем, что напечатал сервер.
5. **Ключ шифрования.** Перенесите `MARKING_SECRETS_KEY` из `C:\marking\.env`
   туда, где храните пароли. **Не** на Яндекс.Диск рядом с копиями.
6. **Обработка 1С** — по `C:\marking\1c\ОБНОВЛЕНИЕ_ОБРАБОТКИ.md`, с проверкой
   на копии базы (в `C:\sync_test`, не в `C:\sync`). Текст модуля — в
   репозитории `1c/ОбменССайтом_МодульОбъекта.txt` (в `C:\marking` его нет:
   каталог `1c/` корня репозитория в программу не входит). Затем в программе: «Диагностика» → «Отправить PING».
7. **Справочники и организация.**
   - «Одежда полный» — загрузить выгрузку каталога Lamoda Seller.
   - «Организации» — проверить реквизиты ИП Яворской и номер последней
     поставки (12550). Там же — OMS ID и ID соединения СУЗ, затем «Войти в
     ЧЗ» (сертификат ИП; токены живут ~10 ч). Без входа Нацкаталог и заказ
     кодов не работают: API-ключа True API не принимает.
   - «Справочник GTIN» — загрузить все прежние файлы `product_gtin`.
     Карточки Нацкаталога программа запросит сама, пока открыта и есть вход
     в ЧЗ: не больше 7 запросов по 25 GTIN за 5 минут, на 1012 пар — около
     получаса.
   - Когда придут первые карточки, проверьте, как в них называются цвет и
     размер, и при необходимости впишите имена на странице справочника.

Программа открывается в браузере этого компьютера: `http://127.0.0.1:8001`.
С других компьютеров её не видно.

## Обновление (рабочий компьютер)

1. Скопируйте новые файлы поверх `C:\marking` (кроме `.env`, `marking.db`,
   `ssh\`, `backups\`, `logs\`, `tools\`, `rclone.conf`, `onec_archive\`).
2. Запустите:
   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\marking\deploy\update_workstation.ps1
   ```
   Скрипт по порядку: остановка программы → копия базы → зависимости →
   миграции → тесты → запуск. Любой сбой — остановка с кодом 1.

## Копия базы в облако (Яндекс.Диск)

У программы свой rclone и свой конфиг. Общий конфиг с sync_admin не
годится: rclone переписывает его при обновлении токена, и две программы
могут испортить файл разом.

1. Положите `rclone.exe` в `C:\marking\tools\`.
2. Настройте доступ к облаку:
   ```powershell
   C:\marking\tools\rclone.exe --config C:\marking\rclone.conf config
   ```
   Выберите: `n` → имя `yandex` → **Yandex Disk** → `client_id` и
   `client_secret` пустые → авторизация в открывшемся браузере.
3. Создайте папку в облаке:
   ```powershell
   C:\marking\tools\rclone.exe --config C:\marking\rclone.conf mkdir yandex:marking_backups
   ```
4. В `C:\marking\.env` пропишите `MARKING_RCLONE_REMOTE=yandex:marking_backups`
   и перезапустите программу (закрыть её процесс или `update_workstation.ps1`).

Копия снимается через 10 минут после запуска программы, потом не чаще раза в
сутки: компьютер на ночь выключают, и расписание «раз в сутки в 3:00» не
наступало бы никогда. База живёт только на этом компьютере — облачная копия
для неё единственная вторая площадка, настраивать её обязательно. Уезжает в облако, после чего программа сверяет размер на той стороне.
Состояние видно на «Диагностике».

## Восстановление из копии

Сначала остановить программу (как в `update_workstation.ps1`):
```powershell
Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like "*markapp.main:app*" } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
# Прежнюю базу ВМЕСТЕ со спутниками -wal/-shm отложить, а не удалять:
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
foreach ($s in @("", "-wal", "-shm")) {
    if (Test-Path "C:\marking\marking.db$s") { Rename-Item "C:\marking\marking.db$s" "marking.db$s.before-restore-$stamp" }
}
Copy-Item C:\marking\backups\marking-ГГГГММДД-ЧЧММСС.db C:\marking\marking.db
```
Затем запустить ярлыком «Маркировка».
Спутники `-wal` и `-shm` убрать от новой базы **обязательно**: иначе SQLite
при первом открытии накатит их поверх копии со страницами прежней базы. Их
переименование выше и есть это «убрать», а прежняя база остаётся целой рядом.

## Запасной вариант: программа на сервере

`install_marking.ps1` / `update_marking.ps1` ставят программу службами NSSM
рядом с sync_admin, обмен с 1С — локальными папками (SFTP не задан). Этот
вариант оставлен на случай, если рабочий компьютер недоступен; для этапа 4 он
не годится — ЧЗ и подпись требуют машины с КриптоПро (ТЗ, разд. 2 и 10).
