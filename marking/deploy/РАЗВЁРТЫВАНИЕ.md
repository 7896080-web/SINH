# Развёртывание программы «Маркировка и поставки» — что и где

> **Что умеет эта версия (этапы 2–3):** поставки Lamoda, проверка остатка и
> перемещение в 1С, УПД из «Поставок FBO», стикеры коробов, справочник GTIN,
> карточки Нацкаталога (по API-ключу), этикетки из готового файла кодов.
> **Чего в ней НЕТ — этап 4:** вход в Честный знак по сертификату (True API и
> СУЗ), заказ кодов, ввод в оборот, файл поставки с кодами. Сейчас ставится
> основа, на которой этап 4 будет работать; подпись и плагин КриптоПро здесь
> проверяются заранее, но в ЧЗ программа пока не ходит.

Три места, и у каждого своё:

| Где | Что там будет | Кто делает |
|---|---|---|
| **Рабочий компьютер с КриптоПро** | сама программа `C:\marking`, её база, ярлык «Маркировка» | вы или Claude на этом компьютере |
| **Сервер 136.243.92.95** | только OpenSSH Server и его настройка | вы, по RDP |
| **1С на сервере** | обновлённая обработка `ОбменССайтом` (общая с sync_admin) | вы, в Конфигураторе |

Порядок важен: ключ для сервера создаёт рабочий компьютер, а ключ сервера
рабочий компьютер может записать только после настройки сервера.

В браузере, войдя в GitHub:
```
https://github.com/7896080-web/sinh/archive/refs/heads/claude/magical-keller-i9x52y.zip
```

Распаковать. Внутри папки `sinh-claude-magical-keller-i9x52y` нужны:

## 1. Рабочий компьютер — установка (≈15 минут)

1. **Python 3.11+** с python.org. При установке — галочка **«Add python.exe
   to PATH»**.
2. Содержимое `marking\` из архива → `C:\marking` (должен получиться файл
   `C:\marking\markapp\main.py`).
3. Проверка компьютера — ничего не меняет, только смотрит (обычный
   PowerShell):
   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\marking\deploy\check_workstation.ps1 -Server 136.243.92.95
   ```
   Ждём: Python есть, OpenSSH-клиент есть, КриптоПро есть, сертификат
   ИП Яворской (ИНН 910223073620) с ключом, True API — 200, СУЗ — 401/400.
   Строки про сервер `:443` пока красные — сервер ещё не настроен, это норма.
4. Установка (права администратора не нужны):
   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\marking\deploy\install_workstation.ps1 -Server 136.243.92.95
   ```
   По ходу:
   - напечатает строку **`ssh-ed25519 AAAA… marking@…`** — скопируйте её,
     она нужна на сервере (шаг 2). Это открытая часть ключа, её можно
     пересылать. Файл `C:\marking\ssh\id_ed25519` (без `.pub`) — закрытый,
     его не пересылать никуда и никогда;
   - скажет «Сервер не ответил на 443 — known_hosts не создан» — норма,
     вернёмся на шаге 3;
   - спросит логин и пароль первого пользователя программы;
   - напомнит про `MARKING_SECRETS_KEY` в `C:\marking\.env` — перенесите это
     значение туда, где храните пароли (НЕ на Яндекс.Диск).
   Тесты внутри должны быть зелёными; один пропущенный — норма.

## 2. Сервер — OpenSSH и настройка (≈10 минут, по RDP)

PowerShell **от администратора**.

1. Скачать `OpenSSH-Win64-vX.X.X.X.msi` (последний, без «Preview») со
   страницы `https://github.com/PowerShell/Win32-OpenSSH/releases` и
   поставить только сервер:
   ```powershell
   msiexec /i C:\путь\OpenSSH-Win64-vX.X.X.X.msi ADDLOCAL=Server
   ```
2. Настройка одним скриптом — в кавычках строка из шага 1.4:
   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\marking_setup\server_sftp_setup.ps1 -PublicKey "ssh-ed25519 AAAA... marking@PC"
   ```
   Скрипт заводит учётную запись `marking_sftp` (только SFTP, только
   `C:\sync`, без пароля и RDP), права на три папки, настраивает SSH на 443,
   брандмауэр и службу. Прежний `sshd_config` сохраняет рядом. Добавьте
   `-AllowFrom <внешний адрес рабочего компьютера>`, если он постоянный, —
   тогда SSH пускает только его.
   - Если включён **брандмауэр Hetzner** — разрешить там 443 тоже и проверить
     правило для ответов на исходящие соединения (`SFTP_1C.md`, «Коротко»,
     п. 3): без него у сервера встанут и sync_admin, и 1С-обмен.
   - Если скрипт говорит, что порт 443 занят другой программой, — стоп,
     напишите мне, что за процесс.
   - Если по SSH на сервер уже кто-то заходит — скажите до запуска: после
     скрипта SSH пускает только `marking_sftp`.
3. В конце скрипт печатает **отпечаток** вида `256 SHA256:AbCd… (ED25519)` —
   сохраните его для шага 3.

## 3. Рабочий компьютер — ключ сервера и проверка связи

1. Запустить установщик ещё раз — он допишет ключ сервера и остальное не
   тронет:
   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\marking\deploy\install_workstation.ps1 -Server 136.243.92.95
   ```
2. Он напечатает отпечаток `SHA256:…`. **Сравнить посимвольно** с
   отпечатком из шага 2.3.
   - Совпал — дальше.
   - Не совпал — удалить `C:\marking\ssh\known_hosts` и остановиться: вы
     говорите не с тем сервером.
3. Проверка SFTP (только смотрим, ничего не кладём):
   ```powershell
   sftp -P 443 -i C:\marking\ssh\id_ed25519 -o UserKnownHostsFile=C:\marking\ssh\known_hosts marking_sftp@136.243.92.95
   ```
   В `sftp>` набрать `ls` — видны `tasks`, `results`, `archive`; затем `bye`.
4. Запуск: ярлык **«Маркировка»** на рабочем столе — синий квадрат с белым
   кодом DataMatrix (`deploy\marking.ico`). Откроется браузер,
   `http://127.0.0.1:8001`, вход логином из шага 1.4.
5. «Диагностика» → **«Проверить плагин КриптоПро»**: должны быть видны
   сертификаты с ИНН, пробная подпись проходит.

Программа установлена. В 1С она пока ничего не шлёт — ждёт шага 4.

## 4. 1С на сервере — обновление обработки (≈1 час, в Конфигураторе)

Полностью — `marking\1c\ОБНОВЛЕНИЕ_ОБРАБОТКИ.md`. Коротко:

1. Выгрузить текущую обработку «ОбменССайтом» в файл
   `ОбменССайтом_до_mark-2.epf` — точка отката.
2. Вставить целиком `1c\ОбменССайтом_МодульОбъекта.txt` в модуль объекта,
   **Ctrl+F7** без ошибок, сохранить как `ОбменССайтом_mark-2.epf`.
3. **Копия базы 1С — и ДО первого входа выключить в ней регламентные
   задания.** Иначе обработка в копии заберёт из `C:\sync\tasks` настоящие
   задания sync_admin и проведёт их в копии.
4. Проверка на копии — **тестовой сборкой с папкой `C:\sync_test`**, не
   `C:\sync` (как её сделать — в инструкции, шаг 4).
5. На бой — `ОбменССайтом_mark-2.epf` (с `C:\sync`, НЕ `_ТЕСТ`).
6. В программе: «Диагностика» → **«Отправить PING»**. Через минуту-две:
   «Обновлена под маркировку: версия mark-3».
   **02.10.2026 обработка на бою уже обновлена (mark-3)** — шаги 1–5
   повторять не нужно, только PING.

## 5. Первое наполнение (в программе, рабочий компьютер)

1. **«Организации»** — проверить реквизиты ИП Яворской, последний номер
   поставки **12550**, ввести **API-ключ Нацкаталога** (ЛК НК → «Профиль» →
   «Данные участника» → «API KEY»).
2. **«Одежда полный»** — загрузить выгрузку каталога Lamoda Seller.
3. **«Справочник GTIN»** — загрузить все прежние файлы `product_gtin`.
   Карточки НК программа запросит сама, пока открыта (≈полчаса на 1012 пар).
4. Когда придут карточки — открыть любую и проверить, что цвет и размер
   разобрались; если нет — вписать имена атрибутов на той же странице.
5. **Облачная копия** — `deploy\README.md`, раздел «Копия базы в облако».
   Обязательно: база живёт только на этом компьютере.

## Готово, если

- ярлык «Маркировка» открывает программу, «Диагностика» без красного;
- плагин видит сертификаты и подписывает;
- PING вернул `mark-3` (проверено 02.10.2026);
- тестовая поставка: «Поставки» → «Новая поставка» → файл, **номер
  поставки — `TEST-1`** (не пустой: пустой взял бы следующий настоящий номер
  12560, а удалённый номер больше не выдаётся) → «Проверить в 1С» возвращает
  остатки по строкам. Проверка в 1С ничего не создаёт. **Перемещение на бою не нажимать**,
  пока не решим, какой поставкой делать первое настоящее.

**Включён VPN** — не работают ни ЧЗ (`ReadTimeout`), ни обмен с 1С (сервер
пускает только адрес офиса). Выключить или внести в исключения `crpt.ru`,
`*.crpt.ru`, `136.243.92.95` (`SFTP_1C.md`, «Что если…»).

Что-то пошло не так — присылайте текст с экрана или
`C:\marking\logs\marking.err.log` (открывать с `-Encoding UTF8`). Закрытый
ключ, `.env` и пароли не присылайте.
