## 2. Что программа умеет сейчас (этапы 2–3 ТЗ и основная часть этапа 4)

- **Поставки Lamoda:** входящий файл (шаблон `fulfilment_shipment`) →
  штрихкод и цена из «Одежды полной» → проверка остатка в 1С
  (`SUPPLY_CHECK`) → перемещение «ЦС Склад → Lamaoda_Склад» одним документом
  (`SUPPLY_MOVEMENT`). Отмены поставки нет; правка — только до перемещения.
- **«Поставки FBO» → УПД** (ядро `upd_constructor/` без изменений), схема
  «комиссия/агентский» по дате УПД, стикеры коробов (`lamoda_stickers/`).
- **«Мэппинг»** — весь каталог Lamoda против справочника баркодов 1С по
  правилам sync_admin (ТЗ 6.2а): статусы, пул штрихкодов, GTIN и НК в одной
  строке, выгрузка отбора в Excel. Справочник — командой `BARCODE_DICT`
  (обработка `mark-2`) или файлом `barcodes_*.txt`.
- **Справочник GTIN** (product_gtin, из «Поставок FBO», вручную) и кэш
  карточек **Нацкаталога** с токеном True API (нужен вход в ЧЗ; лимит
  7 запросов/5 мин). Одного API-ключа True API не принимает (401 «Токен не
  действителен», 30.09); поле API-ключа у организации сейчас не используется.
- **Вход в ЧЗ сертификатом** (`chz_auth.py`): «Организации» → «изменить» →
  «Войти в ЧЗ» (`/organizations/{id}/chz-login`). Плагин подписывает,
  программа сама ходит в `/auth/key` и `/auth/simpleSignIn` (+
  `/{connectionId}` для СУЗ). Токены True API и СУЗ — у организации,
  зашифрованно, ~10 ч. ИНН подписанта сверяется с ИНН организации (из
  подписи, иначе прочитанный страницей; нет ни того ни другого — отказ).
- **«Коды ЧЗ» поставки** (`/supplies/{id}/codes`, после перемещения в 1С, не
  для тестовой поставки; `codes.py`): заказ недостающих кодов в СУЗ (подпись в
  `X-Signature`), получение, фоновый опрос `/cises/info` и итога документов
  `/doc/list` (задание `codes_status`, раз в минуту), ввод в оборот
  `LP_INTRODUCE_GOODS` по кодам «Нанесён» (кнопкой), этикетки PDF по кодам
  поставки, «Коды поставки (.txt)» — только когда все коды в обороте. Нужны
  у организации OMS ID, ID соединения СУЗ и вход в ЧЗ (токен СУЗ). Реестр
  кодов `MarkCode`: короткий КИ открыто, полный — зашифрованно. Заказ или
  документ с неизвестным исходом (таймаут/5xx) — «неизвестно», решает человек
  по ЛК. Сырой ответ СУЗ с кодами — до разбора зашифрованно в
  `<BACKUP_DIR>\codes_journal`; после новых кодов — внеочередная копия базы.
- **Этикетки 58×40** DataMatrix и из готового файла кодов (страница
  «Этикетки»).
- Организации (ИП), нумерация поставок, копия базы с выгрузкой в облако,
  «Диагностика», `/health`. Миграции — до `0006`.

**Чего нет из этапа 4:** владелец GTIN и `goodMarkFlag`/`goodTurnFlag` по
`/product/info`; ограничитель запросов на ИНН для всех обращений к ЧЗ (есть

## 5. Как работать в Claude Code на этом компьютере

**Два каталога, и путать их нельзя:**
- `C:\marking` — **установленная программа с настоящей базой**. Здесь не
  разрабатывают: не правят файлы, не запускают тесты на её базе, не пишут в
  `marking.db` в обход программы.
- `C:\dev\sinh` — **клон репозитория** для разработки:
  ```powershell
  git clone -b claude/magical-keller-i9x52y https://github.com/7896080-web/sinh C:\dev\sinh
  ```
  Клон целиком, не только `marking/`: тесты модуля 1С читают `../1c/`.

**Разработка** — в `C:\dev\sinh\marking`, свой venv, своя `dev.db`, порт
**8011** (`README.md`, раздел «Разработка»). Без `MARKING_ONEC_SFTP_HOST`
обмен идёт в локальные папки — к серверу 1С разработка не обращается. Для
проверок ЧЗ на этапе 4 — только тестовый контур ЧЗ (`chz_contour`) или
методы, ничего не меняющие (вход, статусы, проверка УПД); заказ кодов и ввод
в оборот на бою — только по согласованию с человеком, это деньги и
необратимые документы.

**Тесты — дважды:**
```powershell
cd C:\dev\sinh\marking
python -m pytest -q                       # на этой машине это пояс Москвы
$env:TZ="UTC0"; python -m pytest -q; Remove-Item Env:TZ   # UTC-прогон (на Windows работает)
```
