# Обновление обработки 1С «ОбменССайтом» под программу маркировки

Версия части для маркировки: **mark-2** (функция `ВерсияМодуля()`).
**На бою с 02.10.2026 стоит mark-3** — та же часть маркировки плюс часть
«Репрайсера» (задания `task_price_*`, ответы в `results\pricing`). Программа
маркировки принимает mark-2 и любую новее. Текст боевого модуля —
`../../1c/ОбменССайтом_МодульОбъекта.txt`; по этой инструкции обработку
повторно ставить не нужно — она остаётся для отката и переустановки.
Обоснование — `ТЗ_МАРКИРОВКА.md`, разд. 9.

Обработка **одна на две программы**: sync_admin и маркировка. Поэтому
обновление проверяется на копии базы с обеих сторон (шаг 4). Без проверки на
копии на боевую базу не ставить.

Править можно и по шагам, не заменяя текст целиком: `ВСТАВКА_mark-2_ПОСТРОЧНО.md`
— пять правок к боевому модулю с якорями для поиска. Результат тот же файл.

## Что меняется в модуле

1. Ответы на задания `task_mark_*.txt` идут в подкаталог
   `C:\sync\results\marking`. Ответы sync_admin остаются, где были.
2. Четыре новые команды:
   - `PING` — отвечает версией модуля;
   - `SUPPLY_CHECK` — проверка остатка поставки, документ не создаётся;
   - `SUPPLY_MOVEMENT` — один документ «ЦС Склад → Lamaoda_Склад» на всю
     поставку. Склады в заданиях — **кодами** справочника (ЦБ0000012 →
     ЦБ0000017), обработка ищет их `НайтиСкладПоКоду`;
   - `BARCODE_DICT` (с `mark-2`) — справочник баркодов для страницы
     «Мэппинг», файлом в `results\marking`, а не в общий `results`.
3. Документ поставки: дата **текущая**, комментарий начинается на **`mark`**,
   а не на `sync`. Так sync_admin через минуту увидит, что товар ушёл, и
   перестанет продавать его на WB/Ozon/Kit.

Ветки команд sync_admin (`CREATE_MOVEMENT`, `CANCEL_MOVEMENT` и остальные) не
тронуты.

## Порядок

1. **Резервная копия обработки.** В 1С: «Дополнительные обработки» → карточка
   «ОбменССайтом» → «Выгрузить в файл». Сохраните как
   `ОбменССайтом_до_mark-2.epf`. Это рабочая версия и точка отката.
2. **Правка модуля.** Откройте сохранённый файл в Конфигураторе (Файл → Открыть)
   → «Модуль объекта».
   - Ctrl+A.
   - Вставьте целиком текст файла `1c/ОбменССайтом_МодульОбъекта.txt` из
     репозитория. Вставлять кусками нельзя.
   - **Ctrl+F7** — синтаксический контроль. Ошибок быть не должно.
   - Сохраните как `ОбменССайтом_mark-2.epf`.
3. **Копия базы 1С — и сразу выключить в ней обмен.** Пути обмена в обработке
   зашиты: `C:\sync\tasks`, `results`, `archive` (`ПараметрыОбмена()`). Копия
   базы вместе с данными получает и зарегистрированную обработку с
   расписанием. Если она запустится в копии, то заберёт из `C:\sync\tasks`
   НАСТОЯЩИЕ задания sync_admin: проведёт перемещения в копии, отдаст sync_admin
   «OK» за документы, которых в боевой базе нет, и унесёт задания в архив. Ещё
   она выгрузит в `C:\sync\results` изменения остатков КОПИИ, и sync_admin
   применит их к боевым остаткам. Поэтому **до первого входа в копию**:
   - клиент-серверная база — консоль кластера → свойства копии →
     «Блокировка регламентных заданий включена»;
   - файловая — первым действием в копии: «Дополнительные обработки» →
     «ОбменССайтом» → снять расписание (выключить регламентное задание).
4. **Тестовая сборка и проверка — в СВОЕЙ папке `C:\sync_test`.**
   - Создайте `C:\sync_test\tasks`, `C:\sync_test\results`,
     `C:\sync_test\archive`.
   - Откройте в Конфигураторе `ОбменССайтом_mark-2.epf` из шага 2, в
     `ПараметрыОбмена()` замените в трёх строках `C:\sync` на `C:\sync_test`,
     Ctrl+F7, **сохраните под другим именем**: `ОбменССайтом_mark-2_ТЕСТ.epf`.
     Файл `ОбменССайтом_mark-2.epf` остаётся с `C:\sync` — он пойдёт на бой.
   - Подключите `_ТЕСТ.epf` к копии базы. Положите задания из
     `marking/1c/test_tasks/` в `C:\sync_test\tasks` и запустите обработку
     вручную. Штрихкоды в заданиях — из поставки 12550; если на копии их нет,
     замените на любые существующие.

   | Файл | Ждём в `C:\sync_test\results\marking\` |
   |---|---|
   | `…0001…` PING | `result_mark_…0001….txt`: `ping-copy-1|OK|mark-3|PING` (номер версии — из `ВерсияМодуля()` вставленного текста) |
   | `…0002…` SUPPLY_CHECK | `supplycheck_mark_…0002….txt` (строка на штрихкод, статус `ok` / `short`), затем `result_…`: `lamoda-99990-c1|OK|позиций 2; ЦС Склад -> Lamaoda_Склад|SUPPLY_CHECK` — наименования складов по кодам ЦБ0000012 и ЦБ0000017; другие имена — в копии коды не те |
   | `…0003…` SUPPLY_MOVEMENT | `lamoda-99990|OK|<номер документа>|SUPPLY_MOVEMENT` |
   | `…0003…` ещё раз | **тот же** номер документа, второго документа нет |
   | `…0004…` SUPPLY_MOVEMENT с неизвестным штрихкодом | `lamoda-99991|ERROR|не найден штрихкод 0000000000000|SUPPLY_MOVEMENT`, документа нет вовсе |
   | `…0006…` SUPPLY_CHECK с несуществующим кодом склада | `lamoda-99992-c1|ERROR|Не найден склад с кодом «ЦБ9999999» …|SUPPLY_CHECK` |
   | `…0005…` BARCODE_DICT | сначала `barcodes_mark_…0005….txt` (строка на штрихкод: uid\|артикул\|наименование\|штрихкод\|размер\|цвет), затем `result_…`: `dict-copy-1\|OK\|справочник выгружен\|BARCODE_DICT`. Выгрузка полного справочника идёт минуты — это нормально |

   В копии базы проверьте документ из третьей строки:
   - один документ `ПеремещениеТоваров`, 2 строки, «ЦС Склад» → «Lamaoda_Склад»;
   - дата — **сегодняшняя**;
   - комментарий `mark order_id=lamoda-99990 lamoda проверка на копии базы`.

   Проверьте ещё два места:
   - в `C:\sync_test\results` (не в `marking`) **не появилось** ни одного
     `result_mark_*`;
   - в `C:\sync_test\results\delta_*.txt` после проведения есть строки этих
     штрихкодов с источником «ПеремещениеТоваров», а не `sync`.

   **Проверка стороны sync_admin:** возьмите одно прошлое задание из
   `C:\sync\archive` (`task_*.txt` без `mark`, с одной строкой
   `CREATE_MOVEMENT`), скопируйте его в `C:\sync_test\tasks` и запустите
   обработку в копии. Ответ должен прийти в `C:\sync_test\results`, как
   раньше. В `C:\sync` при всей проверке не должно появиться и пропасть
   ничего, кроме того, что делает боевая обработка.
   - После проверки `_ТЕСТ.epf` и `C:\sync_test` можно удалить. На бой
     `_ТЕСТ.epf` **не загружать никогда**: боевая обработка стала бы читать
     пустую `C:\sync_test`, и sync_admin молча перестал бы получать ответы.
5. **Установка на бой.** В карточке «ОбменССайтом» → «Загрузить обработку из
   файла» → `ОбменССайтом_mark-2.epf` (тот, что с `C:\sync`, НЕ `_ТЕСТ`) →
   записать. Расписание и регистрация
   сохранятся.
6. **Проверка на бою.** В программе маркировки: «Диагностика» → «Отправить
   PING». Через минуту-две должно появиться «Обновлена под маркировку: версия
   mark-3» (02.10.2026 так и пришло). До этого программа задания поставок в 1С не шлёт.

**Откат:** загрузить в карточку файл из шага 1.
