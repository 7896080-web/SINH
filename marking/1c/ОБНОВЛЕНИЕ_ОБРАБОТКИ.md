# Обновление обработки 1С «ОбменССайтом» под программу маркировки

Версия части для маркировки: **mark-1** (функция `ВерсияМодуля()`).
Обоснование — `ТЗ_МАРКИРОВКА.md`, разд. 9.

Обработка **одна на две программы**: sync_admin и маркировка. Поэтому
обновление проверяется на копии базы с обеих сторон (шаг 4). Без проверки на
копии на боевую базу не ставить.

## Что меняется в модуле

1. Ответы на задания `task_mark_*.txt` идут в подкаталог
   `C:\sync\results\marking`. Ответы sync_admin остаются, где были.
2. Три новые команды:
   - `PING` — отвечает версией модуля;
   - `SUPPLY_CHECK` — проверка остатка поставки, документ не создаётся;
   - `SUPPLY_MOVEMENT` — один документ «ЦС Склад → Lamoda_Склад» на всю
     поставку.
3. Документ поставки: дата **текущая**, комментарий начинается на **`mark`**,
   а не на `sync`. Так sync_admin через минуту увидит, что товар ушёл, и
   перестанет продавать его на WB/Ozon/Kit.

Ветки команд sync_admin (`CREATE_MOVEMENT`, `CANCEL_MOVEMENT` и остальные) не
тронуты.

## Порядок

1. **Резервная копия обработки.** В 1С: «Дополнительные обработки» → карточка
   «ОбменССайтом» → «Выгрузить в файл». Сохраните как
   `ОбменССайтом_до_mark-1.epf`. Это рабочая версия и точка отката.
2. **Правка модуля.** Откройте сохранённый файл в Конфигураторе (Файл → Открыть)
   → «Модуль объекта».
   - Ctrl+A.
   - Вставьте целиком текст файла `1c/ОбменССайтом_МодульОбъекта.txt` из
     репозитория. Вставлять кусками нельзя.
   - **Ctrl+F7** — синтаксический контроль. Ошибок быть не должно.
   - Сохраните как `ОбменССайтом_mark-1.epf`.
3. **Копия базы 1С.** Все проверки — только на копии: боевые документы при
   проверке не создаются.
4. **Проверка на копии.** Подключите `ОбменССайтом_mark-1.epf` к копии базы.
   Положите задания из `marking/1c/test_tasks/` в `C:\sync\tasks` и запустите
   обработку вручную. Штрихкоды в заданиях — из поставки 12550; если на копии их
   нет, замените на любые существующие.

   | Файл | Ждём в `C:\sync\results\marking\` |
   |---|---|
   | `…0001…` PING | `result_mark_…0001….txt`: `ping-copy-1|OK|mark-1|PING` |
   | `…0002…` SUPPLY_CHECK | `supplycheck_mark_…0002….txt` (строка на штрихкод, статус `ok` / `short`), затем `result_…`: `lamoda-99990-c1|OK|позиций 2|SUPPLY_CHECK` |
   | `…0003…` SUPPLY_MOVEMENT | `lamoda-99990|OK|<номер документа>|SUPPLY_MOVEMENT` |
   | `…0003…` ещё раз | **тот же** номер документа, второго документа нет |
   | `…0004…` SUPPLY_MOVEMENT с неизвестным штрихкодом | `lamoda-99991|ERROR|не найден штрихкод 0000000000000|SUPPLY_MOVEMENT`, документа нет вовсе |

   В копии базы проверьте документ из третьей строки:
   - один документ `ПеремещениеТоваров`, 2 строки;
   - дата — **сегодняшняя**;
   - комментарий `mark order_id=lamoda-99990 lamoda проверка на копии базы`.

   Проверьте ещё два места:
   - в `C:\sync\results` (не в `marking`) **не появилось** ни одного
     `result_mark_*`;
   - в `delta_*.txt` после проведения есть строки этих штрихкодов с
     источником «ПеремещениеТоваров», а не `sync`.

   **Проверка стороны sync_admin:** на той же копии прогоните одно обычное
   задание `CREATE_MOVEMENT`. Ответ должен прийти в `C:\sync\results`, как
   раньше.
5. **Установка на бой.** В карточке «ОбменССайтом» → «Загрузить обработку из
   файла» → `ОбменССайтом_mark-1.epf` → записать. Расписание и регистрация
   сохранятся.
6. **Проверка на бою.** В программе маркировки: «Диагностика» → «Отправить
   PING». Через минуту-две должно появиться «Обновлена под маркировку: версия
   mark-1». До этого программа задания поставок в 1С не шлёт.

**Откат:** загрузить в карточку файл из шага 1.
