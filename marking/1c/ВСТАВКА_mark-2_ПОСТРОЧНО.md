# Обработка «ОбменССайтом»: доработка боевого модуля под маркировку (mark-2), построчно

Исходник — **боевой модуль**, присланный 01.10.2026 (902 строки). Существующие
строки не удаляются и не переписываются, кроме ОДНОЙ (правка 4); остальное —
вставки. Команды sync_admin (CREATE/CONFIRM/RETURN/SCRAP/CANCEL_MOVEMENT,
выгрузки, справочник, дельта) идут по прежнему коду байт в байт.

Проверено: эти пять правок, применённые к боевому тексту, дают ровно
`1c/ОбменССайтом_МодульОбъекта.txt` из репозитория (1268 строк). Поэтому есть
два равноценных пути: вставить файл целиком (Ctrl+A → вставить) или пройти
правки ниже по одной.

Делать в Конфигураторе: обработка → Модуль объекта. Место искать **поиском
(Ctrl+F) по строке-якорю**, а не по номеру: после первой вставки номера
сдвигаются. Номера ниже — по боевому тексту, для сверки.

Перед началом: «Файл → Сохранить как» → `ОбменССайтом_до_mark-2.epf` (откат).
После всех правок: **Ctrl+F7** — ошибок быть не должно.

		Наименование = ОчиститьПоле(Поз.Номенклатура.Наименование);
		Размер = ОчиститьПоле(Поз.Характеристика);
		Попытка
			Цвет = ОчиститьПоле(Поз.Номенклатура.hiЦвет);
		Исключение
			Цвет = "";
		КонецПопытки;
	КонецЕсли;
	Возврат ОчиститьПоле(Поз.Баркод) + "|" + Уид + "|" + Артикул + "|" + Наименование + "|"
		+ Размер + "|" + Цвет + "|" + Формат(Поз.Остаток, "ЧГ=0; ЧН=0; ЧДЦ=0") + "|"
		+ Формат(Поз.Нужно, "ЧГ=0; ЧН=0") + "|" + Поз.Статус;
КонецФункции

// Коротко для поля ответа: первые пять причин и сколько ещё.
Функция КраткоОбОшибках(Ошибки)
	Первые = Новый Массив;
	Для Каждого Текст Из Ошибки Цикл

			Прервать;

// Перемещение всей поставки одним документом. Возвращает номер документа.
Функция ПереместитьПоставку(ИдЗаказа, КодСкладаОткуда, КодСкладаКуда, Разбор, Примечание)
	// Идемпотентность — ДО проверки остатка: после первого проведения остатка на
	// ЦС уже нет, и повтор задания (ответ на первую попытку потерялся) иначе
	// получил бы отказ «не хватает» вместо номера уже созданного документа.
	СкладКуда = НайтиСкладПоКоду(КодСкладаКуда);
	СуществующийНомер = ПроведённаяПоставка(ИдЗаказа, СкладКуда);
	Если ЗначениеЗаполнено(СуществующийНомер) Тогда
		Возврат СуществующийНомер;
	КонецЕсли;
	Если Разбор.Ошибки.Количество() > 0 Тогда
		ВызватьИсключение КраткоОбОшибках(Разбор.Ошибки);
	КонецЕсли;

	// Склад-отправитель — ТОТ ЖЕ, по которому РазобратьПозицииПоставки сверял
	// остаток (поле 2 задания). Возьми мы здесь свой, проверка смотрела бы на
	// один склад, а документ списывал бы с другого.
	СкладОткуда = НайтиСкладПоКоду(КодСкладаОткуда);
	Документ = Документы.ПеремещениеТоваров.СоздатьДокумент();
	Документ.Дата = ТекущаяДата();
	Документ.СкладОтправитель = СкладОткуда;
	Документ.СкладПолучатель  = СкладКуда;
	Документ.МагазинОтправитель = СкладОткуда.Магазин;
	Документ.МагазинПолучатель  = СкладКуда.Магазин;
	Документ.Комментарий = "mark order_id=" + ИдЗаказа + " lamoda " + Примечание;
	СтрокиПоТовару = Новый Соответствие;
	Для Каждого Поз Из Разбор.Позиции Цикл
		СтрокаТовара = СтрокиПоТовару.Получить(Поз.Ключ);
		Если СтрокаТовара = Неопределено Тогда
			СтрокаТовара = Документ.Товары.Добавить();
			СтрокаТовара.Номенклатура = Поз.Номенклатура;
			СтрокаТовара.ХарактеристикаНоменклатуры = Поз.Характеристика;
			СтрокаТовара.Количество = 0;
			СтрокаТовара.ЕдиницаИзмерения = Поз.Номенклатура.ЕдиницаХраненияОстатков;
			СтрокаТовара.Коэффициент = 1;
			СтрокиПоТовару.Вставить(Поз.Ключ, СтрокаТовара);
		КонецЕсли;
		СтрокаТовара.Количество = СтрокаТовара.Количество + Поз.Нужно;
	КонецЦикла;
	Документ.Записать(РежимЗаписиДокумента.Проведение);
	Возврат Строка(Документ.Номер);
КонецФункции

// Склад по КОДУ справочника «Склады» — только для поставок маркировки.
// Код ищем точным совпадением и требуем ровно один непомеченный на удаление
// элемент: справочник подчинён магазинам, и уникальность кода в пределах
// подчинения не исключена. Два склада с одним кодом — отказ, а не выбор
// наугад: перемещение поставки не отменить.
Функция НайтиСкладПоКоду(Код)
	КодСклада = СокрЛП(Код);
	Если ПустаяСтрока(КодСклада) Тогда
		ВызватьИсключение "В задании не указан код склада";
	КонецЕсли;
	Запрос = Новый Запрос;
	Запрос.Текст =
		"ВЫБРАТЬ ПЕРВЫЕ 2 Склады.Ссылка КАК Ссылка
		|ИЗ Справочник.Склады КАК Склады
		|ГДЕ Склады.Код = &Код И НЕ Склады.ПометкаУдаления";
	Запрос.УстановитьПараметр("Код", КодСклада);
	Выборка = Запрос.Выполнить().Выбрать();
	Если НЕ Выборка.Следующий() Тогда
		ВызватьИсключение "Не найден склад с кодом «" + КодСклада + "» — проверьте код в справочнике Склады.";
	КонецЕсли;
	Склад = Выборка.Ссылка;
	Если Выборка.Следующий() Тогда
		ВызватьИсключение "Код склада «" + КодСклада + "» есть у нескольких складов — укажите однозначный.";

	Возврат Склад;
КонецФункции

// Номер уже проведённой поставки по order_id на этот склад — или пустая строка.

## Почему боевому обмену это не вредит

- Новые ветки срабатывают только на командах PING, BARCODE_DICT,
  SUPPLY_CHECK, SUPPLY_MOVEMENT — sync_admin их не шлёт никогда.
- Существующие функции не тронуты. Общую `НайтиНоменклатуруПоШтрихкоду`
  поставка не использует — у неё своя `ТоварПоставкиПоШтрихкоду`.
- Ключи перемещений поставки — `lamoda-<номер>`. С номерами заказов WB, Ozon
  и Kit они не совпадают, поэтому ни идемпотентность `CREATE_MOVEMENT`, ни
  `CANCEL_MOVEMENT` документов поставок не заденут.
- Комментарий документа поставки — `mark …`, не `sync …`: дельта остатка ЦС
  дойдёт до sync_admin как обычное движение, и отгруженное на Lamoda не будет
  продаваться на WB/Ozon/Kit.
- sync_admin забирает из `C:\sync\results` только файлы верхнего уровня
  (`result_*`, `stock_*`, `barcodes_*`…), в `results\marking` не заглядывает.
