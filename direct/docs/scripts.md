# Скрипты — что делает каждый и как запускать

Все запускаются из `C:\direct`: `python <скрипт>.py`. «Пишет» — меняет настройки в кабинете
(без `--apply` — пробный прогон).

## Яндекс Директ
| Скрипт | Тип | Что делает |
|---|---|---|
| `direct_check.py` | чтение | Состояние кампаний: стратегия, бюджеты, запрещённые площадки, корректировки, объявления, расход по дням |
| `direct_before_after.py [ГГГГ-ММ-ДД]` | чтение | Сравнение «до» (29.09–05.10) и «после» (с указанной даты, по умолчанию 06.10): расход, покупки, доля рекламы, структура расхода по возрасту/устройствам/регионам/площадкам |
| `direct_deep_report.py` | чтение | Площадки, запросы, группы, аудитория за 30 дней (конверсии ЕПК в API нулевые — смотреть Метрику) |
| `direct_feeds.py [url фида]` | чтение | Фиды: статус, обновление, проверка XML (опечатки брендов, размеры, производители) |
| `direct_frequency.py` | чтение | Частота показов на человека (для ЕПК отчёт пустой) |
| `direct_campaigns.py` | чтение | Список кампаний и статистика за 30 дней (первый скрипт проекта) |
| `direct_stage1.py [--apply/--rollback]` | пишет | Этап 1 аудита: бюджеты, запрещённые площадки, корректировки (применён 06.10) |
| `direct_age_45_54.py [-N] [--apply/--rollback]` | пишет | Корректировка ставки для возраста 45–54 (сейчас −20%); знак обязателен: `-30`, `+10` |
| `direct_awer_jackets.py [--apply/--rollback]` | пишет | Ссылки объявлений КО курток → коллекции AWER (модерация) |

## Wildberries (токены — `wb_tokens.txt`; общий модуль `wb_common.py`)
| Скрипт | Тип | Что делает |
|---|---|---|
| `wb_positions.py [--cabinet X] [--backfill N] [--report]` | чтение | Позиции в поиске и воронка по дням с историей в `wb_history.db` («Джем»): медианная/средняя позиция товара и кабинета, позиции по каждому запросу, свой список запросов `wb_watch.csv`, сигналы с причинами; графики `wb_positions.html`. Кабинеты собираются одновременно — 5–15 мин на все |
| `wb_promo_pos.py [--cabinet К] [--nm A,B] [--day ГГГГ-ММ-ДД] [--to ГГГГ-ММ-ДД]` | читает | Акция WB: позиции в поиске «вчера → сейчас» (или два полных дня): цена товара в поиске и средняя цена заказа (кто в акции), средняя и медианная позиция, видимость, позиции по запросам (сколько выше/ниже), переходы из поиска и заказы — темп к вчерашнему к этому же часу; неделю назад — из `wb_history.db`. Главный вывод — разница групп «в акции / без акции» (общие колебания дня у них одинаковы). Свежие данные — во временную базу, `wb_history.db` не меняет. Отчёт `wb_promo_pos_report.txt`, таблица `wb_promo_pos.csv` |
| `wb_daily.py [--cabinet X]` | чтение | Утренний отчёт: вчера против недели, остатки, «что сделать сегодня» (включает сигналы `wb_positions.py`); кабинеты опрашиваются одновременно |
| `wb_unit.py [дней]` | чтение | Юнит-экономика по артикулам из отчётов реализации; пишет `wb_unit_economics.csv`, шаблон `wb_cost.csv` |
| `wb_queries.py` | чтение | Поисковые запросы (частотность WB), ВЧ/СЧ/НЧ, действия по запросам |
| `wb_organic.py [--days N]` | чтение | «Контроль органики»: запросы, где товар и так в топе, а мы платим за рекламу; брендовые запросы; как проверить экспериментом (только отчёт, по `wb_history.db`) |
| `wb_weekday.py [дней]` | чтение | Реклама по дням недели (цена заказа, устойчива ли разница), все заказы по дням и часам, спрос по дням из «Джема»; вывод — нужен ли дневной лимит по дням недели |
| `wb_weekly.py [недель]` | чтение | Недельные отчёты WB о реализации: продажи, логистика, хранение, удержания, «к оплате» по неделям; последняя неделя против прошлой по товарам (выросли/упали), удержано за рекламу. Раздел «Финансы», с автопилотом по лимитам не пересекается |
| `wb_hours.py [дней] [--models 27643,36446]` | чтение | Заказы выбранных моделей по часам и дням недели; какая доля заказов дня приходится на часы после любого момента — чтобы выбрать дневной лимит рекламы |
| `wb_dashboard.py [--no-open]` | чтение | Дашборд `wb_dashboard.html`: плитки (расход, заказы с рекламы, цена заказа, все заказы, ДРР — к прошлому периоду), графики по дням (расход, заказы, цена заказа, позиции топ-4), автопилот (запуски, пополнения против потолков, последняя часовая проверка), таблица товаров с поиском и сортировкой. Без токена и запросов к WB — из `wb_history.db` и файлов автопилота |
| `wb_cancels.py [дней] [--models 27643,36446]` | чтение | Отмены заказов: доля и сумма, кто отменил (продавец / покупатель в первый час / при получении / WB — по сборочным заданиям FBS, нужна категория «Маркетплейс»), через сколько после заказа, по складам, артикулам, размерам, регионам |
| `wb_clusters.py [дней] [--campaign ID]` | чтение | Поисковые кластеры активных кампаний за показы (с `--all` — и на паузе): что покупает каждая кампания (показы, клики, заказы, расход, цена заказа, позиция, ставка на кластер), активные и исключённые, кандидаты на исключение. У кампаний за клики WB кластеров не даёт |
| `wb_dayparts.py [--models 27643,36446]` | чтение | Спрос по часам с учётом дня недели (все заказы за 90 дн.): таблица «день недели × час», доли ночь/утро/день/вечер, проверка, устойчиво ли различаются дни недели (хи-квадрат), кривая «к какому часу набирается доля спроса» по дням недели → `wb_dayparts_profile.csv` |
| `tools/sim/sim.py <папка> <дней>` (и `sim2.py`) | проверка кода | Модель долгой работы автопилота, стража, сборщика и `wb_budget.py` на имитации WB с виртуальными часами (к WB не обращается): нарушения потолков, двойные пополнения, зависшие паузы, рост файлов. Отчёт — `<папка>/_report.txt`. Запускать после крупных правок |
| `wb_guard.py --limits [--apply]` | изменения | Частая проверка своего дневного лимита (каждые 5 мин с 7:02): кампании за показы и за клики с лимитом ниже 1 000 ₽ — пауза до утра, пауза «по графику» (расход обогнал спрос по часам), запуск, когда спрос догнал и запас больше 5-минутного расхода; ночью (23:30–7:00) стоят. Ставки и пополнения не трогает. Журнал — `wb_limits_log.txt` (только паузы, запуски, ошибки) |
| `wb_cpm_stop.py [--apply/--rollback]` | пишет | Промежуточная проверка эксперимента (решение пользователя 15.10.2026: «проверка 20.10, если показы без заказов — остановить»): кампании за показы Ребрика и Карамана из RULES с 14.10 по вчера; потратила ≥ 1 000 ₽ и ни одного заказа — `--apply` вписывает в `wb_hold.txt` и ставит на паузу (раньше 20.10 не применяет); рядом — цена заказа у кампаний за клики. Откат — только последний запуск, сразу: убирает из стоп-листа, кампании запускает частая проверка лимита по графику |
| `wb_hold.txt` | стоп-лист | Номера кампаний по одному в строке (после `#` — комментарий): автопилот, часовая и частая проверки их **не запускают и не пополняют**. Нужен, чтобы выключить кампанию со своим лимитом — её скрипты сами ставят на паузу (ночью, по лимиту, по графику), и обычная пауза в кабинете WB от их паузы не отличается. Действует со следующей проверки; пауза становится «вашей». Вернуть: убрать номер из файла и запустить кампанию в кабинете WB — дальше скрипты снова ею управляют |
| `wb_collector.py [--status]` | чтение | Сборщик рекомендованных ставок и размеров WB (каждые 15 мин, 7:00–24:00): база `wb_rec.db` — последняя рекомендация каждого товара кампании, размеры (раз в 2 ч), история изменений рекомендаций (60 дн.). Ждёт, пока автопилот или проверка сами спрашивают WB (`wb_api.busy`). `COLLECTOR_MODE` в `wb_bids.py`: `check` — автопилот и проверка сверяют свои ответы WB с базой (`wb_rec_check.csv`), `use` — берут из базы. `--status` — свежесть и сверка |
| `wb_seo_queries.py [дней]` | чтение | Успешные поисковые запросы по категориям (все кабинеты, по `wb_history.db`): библиотека `wb_seo_library.csv` копится, задачи SEO для похожих товаров — `wb_seo_tasks.csv` (каких слов нет в названии). Каждый день после `wb_positions.py` |
| `wb_before_after.py [дата начала] [дней до] [--cabinet имя]` | чтение | Реклама «до» и «после» нашего управления (по умолчанию: 14 дн. до 13.10.2026 — первого `wb_bids.py --apply` — против 13.10 — вчера): кабинет целиком в день (расход, показы, клики, CTR, цена клика, заказы с рекламы, цена заказа, ДРР рекламы, все заказы кабинета, общий ДРР) и каждая кампания (в день — по дням с расходом), вывод «лучше / хуже / в пределах случайности» по ожидаемым заказам при прежней отдаче → `wb_before_after.txt`, `wb_before_after.csv` |
| `wb_pacing.py [дней]` | чтение | Равномерность расхода по часам: во сколько у каждой кампании кончаются деньги (за клики — дневной лимит, за показы — бюджет) и какая доля дневного спроса упущена. Данные — `wb_spend_hourly.csv`, его каждый час пишет `wb_guard.py` (с 14.10.2026) |
| `wb_reviews.py [дней] [--models 27643,36446]` | чтение | Отзывы: оценки по артикулам и цветам, «маломерит / большемерит» по размерам, отказы и возвраты среди отзывавшихся, темы жалоб (цвет, размер, качество, ткань), последние плохие отзывы. Нужна категория «Вопросы и отзывы» |
| `wb_campaigns.py [--all]` | чтение | Снимок кампаний: статус, тип ставки, оплата, места, товары со ставками и остатками, бюджет, дневной лимит, минус-фразы, итог 7 дней; предупреждения (товар в нескольких кампаниях, реклама без остатка, нет лимита). Снимок с датой — в `wb_snapshots\` |
| `wb_ads_report.py [дней]` | чтение | Реклама по всем кабинетам: кампании, товары, кластеры, оценка выкупа |
| `wb_bids.py [--apply/--rollback]` | пишет | Автопилот: ставки, ставки на запросы, минус-фразы, дневные лимиты — только кампании из `RULES` |
| `wb_web.py` (ярлык «Реклама WB») | пишет | «Реклама WB» в браузере (только на этом компьютере, 127.0.0.1 с одноразовым ключом, порт 8765): две страницы — «Дашборд» (как `wb_dashboard.html`) и «Бюджеты»: по кабинетам кампании с номером, названием, статусом и **артикулами** (артикул продавца и номер WB), дневной лимит, пополнения в сутки, недельный потолок, пополнено за 7 дней, недельный бюджет кабинета, **рекомендуемый бюджет** с пояснением и кнопкой «Взять» (расчёт — `wb_budget.py`, раз в сутки; «Пересчитать сейчас» — пробный прогон `wb_budget.py`); поиск по номеру/артикулу. «Проверить» — план и предупреждения (не кратно 1 000, меньше 7 дневных лимитов, лишний ноль, потолок 0, эксперимент, сумма потолков больше бюджета кабинета), «Сохранить» — `wb_budget_overrides.json` с копией в `wb_budget_backups`, «Отменить последнее сохранение» — как `wb_budget.py --rollback`. Править можно только кампании под управлением автопилота; поправленные вручную `wb_budget.py` не трогает. Снижение потолков — сразу, повышение — с ближайшего автопилота, свой дневной лимит — за 5 мин. Фильтр «только под управлением» (по умолчанию; кампании не под управлением — в свёрнутом списке с причиной). У кнопок — шкала прогресса (загрузка по кабинетам, пересчёт по этапам из `wb_budget_progress.json`); пока действие идёт, кнопки выключены. Не поднялся сервер — открывает файл дашборда, как раньше |
| `wb_budget.py [--apply [--only ID,ID]]`, `--rollback` | пишет (лимиты) | Бюджет по окупаемости: кампаниям, у которых заказ с рекламы дешевле допустимого (≤ 90%), а деньги кончаются раньше 20:00 (часовые снимки), — прибавка к дневному лимиту и потолкам пополнений (+15/30/50% по запасу окупаемости), не чаще раза в 7 дней; через 7 дней проверка — не окупилось → вернуть. Пишет `wb_budget_overrides.json`, автопилот и страж берут его поверх `RULES`. Деньги не переводит. Предложения — в `wb_budget_proposals.json` и на дашборде, ход расчёта — в `wb_budget_progress.json` (для шкалы на странице «Бюджеты»); пробный прогон раз в сутки после автопилота делает `wb_run.py` |
| `wb_minus.py --campaign ID --nm артикул --add "фраза; фраза" [--apply]`, `--rollback` | пишет | Минус-фразы одному товару в одной кампании вручную: читает текущий список и дописывает, резервная копия, после записи перечитывает у WB и показывает, сохранилось ли. Откат — только последний запуск |
| `wb_trim.py [порог] [--apply/--rollback]` | пишет | Убрать из активных кампаний товары с остатком меньше порога (по умолчанию 15 шт, WB + свой склад; то же правило применяет автопилот `wb_bids.py`); кампанию целиком не опустошает; откат возвращает товары и их ставки |
| `wb_guard.py [--apply/--rollback]` | пишет | Часовая проверка ставок между прогонами автопилота: до 40 самых кликабельных товаров сверяет с рекомендацией WB и двигает ставку за ней в обе стороны — не выше окупаемого потолка из последнего `wb_bids.py --apply`, вниз — сразу, вверх — сразу, но не выше окупаемого потолка, не ниже минимума WB; ставку ниже нового минимума поднимает, только если минимум не выше потолка, иначе сообщает; бюджет меньше порога → пополняет по правилам автопилота (и запускает, если кампания встала из-за денег). Пока идёт `wb_bids.py`, ничего не делает; потолки старше 2 суток — ничего не меняет |
| `wb_schedule.ps1 [-Remove] [-Server]` | настройка | Ставит в Планировщик заданий Windows: `wb_positions.py` в 6:00, `wb_bids.py --apply` в 8:00, 13:00, 18:00 и `wb_guard.py --apply` каждый час в :40 (7:40–23:40), `wb_collector.py` каждые 15 мин (7:00–24:00), `wb_guard.py --limits --apply` каждые 5 мин (7:02–24:00); после каждого запуска (кроме сборщика и частой проверки) пересобирает дашборд `wb_dashboard.html`. С 14.10 — через `wb_run.py` (без окна, от батареи тоже). Запускать после первого удачного ручного `--apply` |
| `deploy/export_for_server.ps1` | переезд | Рабочий компьютер (из `C:\sinh\direct\deploy`): снимает расписание, кладёт `MOVED_TO_SERVER.txt` (скрипты здесь больше не запускаются), ждёт запущенные, снимает проверенные копии баз, берёт из AWER CRM только нужные ключи в `crm_config.json`, собирает `C:\temp\direct_move.zip` (с токенами — только по RDP). Подробно — `deploy/ПЕРЕЕЗД.md` |
| `deploy/install_server.ps1` | переезд | Сервер, от администратора: свой venv, права, проверка баз и скриптов, связь с WB (список кампаний, только чтение), пробный прогон `wb_guard.py --limits`, по «да» — расписание от SYSTEM, ярлык «Реклама WB» через Chrome/Edge |
| `deploy/make_update.ps1` / `deploy/update_server.ps1 [-Rollback]` | обновление | После переезда: рабочий компьютер собирает `C:\temp\direct_update.zip` (только код, `VERSION.txt`); сервер выключает расписание, ждёт скрипты, копирует прежний код в `code_backups`, ставит новый, проверяет и включает расписание (не загрузилось — возвращает прежний) |
| `wb_run.py <скрипт> [аргументы] --timeout мин` | служебный | Запуск по расписанию: без окна (pythonw), останавливает зависший скрипт и снимает его блокировку, переносит журналы больше 5 МБ в `*.old.txt`, затем пересобирает дашборд. Вывод — в `wb_sched_out.txt` |
| `wb_dashboard_shortcut.ps1` | настройка | Ярлык «Реклама WB» на рабочем столе (иконка `wb_dashboard.ico`): пересобрать дашборд и открыть, без окна консоли |
| `wb_create.py --name … --pay cpm/cpc --where … --from …` | пишет | Создание кампаний; `--start ID`, `--pause ID`, `--deposit ID --budget N` — тоже пробный прогон, выполняются с `--apply` |

## Файлы состояния (не удалять, не коммитить)
- `direct_backups\` — резервные копии изменений Директа.
- `wb_bids_backups\`, `wb_bids_state.json` — резервные копии и состояние автопилота WB (какие минус-фразы добавил он).
- `wb_cost.csv` — себестоимость по артикулам (заполняет пользователь).
- `wb_watch.csv` — «мои запросы» для отслеживания позиций: `кабинет;артикул WB;запрос;цель позиции;заметка`
  (заполняет пользователь; строки с `#` в начале пропускаются; можно указать артикул без запроса — товар просто
  попадёт в отслеживание).
- `wb_history.db` — история позиций, запросов, воронки и рекламы (SQLite; растёт с каждым днём, хранится 400 дней).
  Не удалять — без неё не будет сравнения «сейчас/было» и графиков.
