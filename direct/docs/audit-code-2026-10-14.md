Четыре независимых проверки: автопилот `wb_bids.py`; `wb_guard.py`, расписание и пишущие скрипты; сверка всех

## 1. Сверка с документацией WB
- Все ~45 методов, которые используют скрипты, есть в актуальной спецификации, HTTP-методы верные, ключи запросов
  и ответов (регистр, вложенность), единицы (копейки / рубли), допустимые значения — совпадают. Мест, где скрипт
  читает несуществующее поле и молча получает пустоту, не найдено.
- Устаревшие методы, которые WB отключает (`GET /adv/v1/budget` — 16.11, `goods-return` — 26.10, `region-sale` — 03.11),
  скриптами **не используются**.
- Паузы `pace()` соответствуют лимитам WB для персонального токена.
- Не подтверждено документацией: текущая ставка кампаний с единой ставкой читается из поля `search`
  (в спецификации у `bids_kopecks` есть только `search` и `recommendations`); на живых данных пока работает.
- Ограничения API по природе: статистика заказов (`/api/v1/supplier/orders`) может не содержать заказы с отложенной
  оплатой / рассрочкой — WB советует «Ленту заказов» (`/api/analytics/v1/order-feed`). Минус-фразы у кампаний за
  клики невозможны (проверено 14.10, ответ 404).

## 5. Расписание и Windows
- Задачи запускаются через `cmd /c`: при срабатывании ограничения по времени может остаться висеть `python.exe`
  (не проверено на Windows), дашборд после такого не пересобирается, блокировка остаётся.
- Задачи работают только пока вы вошли в систему (окно cmd каждый час; закрыли окно — оборвали применение).
- На ноутбуке от батареи задачи не стартуют и останавливаются при отключении зарядки (настройки по умолчанию).
- Журналы `wb_sched_out.txt`, `wb_guard_log.txt`, `wb_bids_log.txt` только растут (≈100 МБ в год), дашборд
  перечитывает их целиком каждый час.
- Ручной запуск с перенаправлением вывода в файл (`> файл`) может упасть на символах ₽ ═ ✓ (кодировка cp1251).
- Пауза между запросами (`pace`) работает только внутри одного процесса: `wb_positions` (6:00, ~1 ч), страж (7:40) и
  автопилот (8:00) на одном токене мешают друг другу → ответы 429 и пропуски данных.

## 6. Ускорение
- **Кабинеты параллельно** (лимиты WB — на продавца, а у нас три продавца): автопилот и страж ~в 3 раза быстрее,
  `wb_positions` с ~1 ч до ~20 мин. Заодно сужается окно гонки Д2.
- **Пакетные чтения:** бюджеты и дневные лимиты — одним запросом на кабинет, а не по кампании (−~2 мин у Яворской);
  воронка — один запрос на все товары (`nmIds: []`, `limit: 1000`); кластеры по дням — `POST /adv/v1/normquery/stats`
  одним вызовом вместо цикла по дням.
- **Кэш:** рекомендации WB (страж через 40 мин после автопилота спрашивает то же самое), выкуп и остатки по размерам — раз в сутки.
- **Одна копия `call/pace/load_tokens`** в `wb_common.py` вместо трёх (в `wb_bids.py`, `wb_create.py`) — исправления
  делаются в одном месте.
- Страж в 7:40 сдвинуть на 7:20 или пропускать запуск, если автопилот применял меньше часа назад.

## 7. План исправлений
**Этап 1 — деньги (Д1–Д8, Л1) — сделан 14.10, проверен на имитации API:** без повторов для пополнений/запуска/создания с перепроверкой бюджета после
тайм-аута; одна общая блокировка для автопилота и стража (с номером процесса), перечитывание состояния и потолков
перед каждым пополнением и сохранение сразу после; атомарная запись состояния и остановка при испорченном файле;
лимит никогда не понижается из-за нехватки бюджета; кабинет в записи пополнения и недельный бюджет по всем
кампаниям кабинета; при сбое кабинета — сохранять его прежние потолки; список убранных — только из состояния;
запуск после пополнения — только если кампания остановилась сама (кончились деньги), а не поставлена на паузу.
**Этап 2 — отчёты и логика (О1–О7, Л2–Л6) — сделан 14.10, проверен на имитации API.** Не сделано из О7: заказы с рассрочкой («Лента заказов» вместо статистики) — отдельная доработка; даты по часам компьютера — оставлено (компьютер в московском поясе).
**Этап 3 — скорость и расписание — сделан 14.10:** кабинеты считаются одновременно (автопилот и страж; время ≈ по
самому большому кабинету — Яворской, а не сумма трёх); бюджеты и дневные лимиты — одним запросом на кабинет;
расписание через `wb_run.py` (без окна, своё ограничение времени со снятием блокировки, работа от батареи, перенос
журналов > 5 МБ); дашборд: «7 дней» считаются по местной дате. Не делалось (польза меньше риска): общий кэш
рекомендаций для стража (ему нужны свежие), общая пауза запросов между процессами (автопилот и страж теперь не
работают одновременно), параллельные кабинеты в `wb_positions.py` (идёт в 6:00, время не критично), запуск заданий
без входа в Windows (S4U требует прав администратора — по желанию).
