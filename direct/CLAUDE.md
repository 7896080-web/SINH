# AWER — реклама и аналитика (Яндекс Директ, Метрика, Wildberries)

Папка `C:\direct` — рабочие Python-скрипты для рекламы и аналитики бренда мужской одежды AWER:
Яндекс Директ / Метрика / Вебмастер / Яндекс Доставка для сайта awer-russia.ru (Яндекс KIT) и
Wildberries (реклама, продажи, юнит-экономика, поисковые запросы, позиции в поиске и воронка).

  Давай команды целиком, готовые к вставке в PowerShell.

  работают на сервере с 1С/sync_admin (Windows Server 2016, RDP) в том же `C:\direct` (установлены 16.10.2026 02:09),
  расписание — от SYSTEM (`wb_schedule.ps1 -Server`), Python — `C:\direct\.venv`. **Пояс сервера — FLE (Киев), не
  московский:** до 25.10 совпадает с Москвой, потом на час позади; расписание задано по Москве в UTC, скрипты по
  расписанию считают время по Москве (`wb_run.py`: `TZ=MSK-3`), ручной запуск — по часам сервера. На рабочем компьютере `C:\direct` помечен
  `MOVED_TO_SERVER.txt` — скрипты там не запускаются. Обновления — не `git pull` + `Copy-Item`, а

## Правила безопасности — соблюдать всегда
1. **Токены не читать, не выводить, не коммитить.** Они в `wb_tokens.txt`, `yandex_delivery_token.txt`,
   `crm_config.json` (на сервере) и `~/AWER CRM/config.json` (чтение запрещено в `.claude/settings.json`). Скрипты сами их читают.
   Никогда не вписывать токен в код.
2. **Любое изменение рекламы — сначала пробный прогон** (запуск без `--apply`), показать план пользователю,
   применять `--apply` только после явного «да». У пишущих скриптов есть резервная копия и `--rollback`.
   Новые пишущие скрипты делать по той же схеме: пробный прогон → `--apply` с бэкапом → `--rollback`.
   **Откат ограничен** (подробно — `docs/architecture.md`, раздел 3): возвращает только последний запуск, применяется
   сразу без пробного прогона, перезаписывает ручные правки; `direct_stage1.py --rollback` вернёт недельный бюджет
   к 47 500 / 37 500 ₽ (45–54 с 14.10 не трогает); у `wb_create.py` отката нет. Предупреждать об этом до любого отката.
3. Не менять стратегию и цели кампаний Директа без обсуждения — это сбрасывает обучение.
4. WB: строгие лимиты API — соблюдать паузы (`pace()` в скриптах); нужен «Персональный» токен.
   Минус-фразы WB при записи **заменяют весь список** — всегда читать текущие и дописывать.
5. После правки скрипта: `python -m py_compile <файл>`; проверять логику на имитации API (моках),
   прежде чем просить пользователя запускать на живом кабинете.

## Как писать новые скрипты
- Python 3, только `requests` (+ стандартная библиотека). UTF-8, комментарии и вывод — по-русски.
- Вверху — docstring: что делает, как запускать, какие категории токена нужны.
- Настройки — константами в начале файла с понятными комментариями.
- Результат: вывод на экран + `*.txt` отчёт; таблицы — CSV с разделителем `;` в `utf-8-sig` (для Excel).
