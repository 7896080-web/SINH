# Внешняя обработка 1С «ВыгрузкаПродажДляБота»

База: обычное приложение (обычные формы). Продажи по продавцам есть в двух местах:
* **чеки ККМ** (`Документ.ЧекККМ`) — информативнее: номер чека и время → средний чек, вещей в чеке,
  доля чеков «одна вещь» по каждому продавцу, лучшие часы;
* **«Отчет о розничных продажах»** (ОРП) — сводно по кассе за смену: продавец в строке есть, номера чека нет.

Обработка умеет оба источника (реквизит `Источник` = «Чеки» / «ОРП»). **Начните с «Чеки»**; если чеки после
закрытия смены в базе не хранятся (список «Чеки ККМ» за прошлые дни пуст) — переключите на «ОРП».
Бот сам понимает, что пришло: при «ОРП» средний чек и вещей в чеке считает по магазину, а по продавцу —
по покупкам клиентов с дисконтной картой (строки одной карты в одном документе = одна покупка).

Исходники: `onec/ВыгрузкаПродажДляБота/МодульОбъекта.bsl`, `МодульФормы.bsl`.
Собирается в Конфигураторе в `ВыгрузкаПродажДляБота.epf` (бинарник в git не храним).

## Что выгружает (CSV, UTF-8, `;`)

| Файл | Содержимое | Зачем |
|---|---|---|
| `sales_*.csv` | Дата;Время;Склад;Документ;Чек;Продавец;Номенклатура;Номенклатурная группа;Количество;Цена;Сумма;Скидка;Ручная скидка %;Дисконтная карта | план, ступени, качество продаж; возвраты с минусом; пустой продавец → «(без продавца)» (видно владельцу) |
| `orp_docs_*.csv` | Дата;Магазин;Касса;Документ;Чеков;Чеков возврата;Выручка | признак «смена закрыта» (проведённый ОРП), средний чек магазина |
| `stock_*.csv` | Дата;Склад;Номенклатура;Номенклатурная группа;Характеристика;Остаток | советы только по товару в наличии; владельцу — «битые» размеры и залежавшийся товар |
| `arrivals_*.csv` | Дата;Склад;Документ;Номенклатура;Номенклатурная группа;Характеристика;Поступило;Бренд;Цвет | продавцам утром — что пришло нового; в бот «Обучение» — карточка новинок с брендом и цветом |

Скидка = Цена × Количество − Сумма. Ручная скидка — по колонке «% Руч. ск.» (владельцу, продавцам не показывается).
Остатки и поступления — только складов магазинов: реквизит `СкладыМагазинов` (подстроки через `;`, по умолчанию
`ГОРОД;МСЛ`). Магазин определяется по складу/кассе через `config.yaml → onec.store_map`.

## Сборка в Конфигураторе

1. **Файл → Новый… → Внешняя обработка.** Имя `ВыгрузкаПродажДляБота`, синоним «Выгрузка продаж для бота».
2. **Реквизиты:** `ДатаНачала` (Дата, состав «Дата»), `ДатаОкончания` (Дата), `КаталогВыгрузки` (Строка, неогр.),
   `Источник` (Строка 10: «Чеки» / «ОРП»), `СкладыМагазинов` (Строка, неогр.).
3. **Действия → Открыть модуль объекта** — вставить `МодульОбъекта.bsl`.
4. **Формы → Добавить** — тип «Форма обработки», **обычная форма**. Разместить поля реквизитов,
   кнопку «Выгрузить» с действием `КнопкаВыгрузитьНажатие`. В модуль формы вставить `МодульФормы.bsl`.
   В свойствах формы событие «ПриОткрытии» → `ПриОткрытии`.
5. **Сверить имена метаданных** (пометки `ПРОВЕРИТЬ`):
   * `Документ.ЧекККМ`: ТЧ `Товары` (`Продавец`, `Цена`, `Сумма`, `ПроцентСкидкиНаценки`), шапка `Склад`, `КассаККМ`,
     `ДисконтнаяКарта`, `ВидОперации` (Продажа/Возврат), статус `СтатусЧекаККМ` (Пробитый или Пробит / Архивный);
     если продавец в шапке чека — `Т.Ссылка.Продавец` или `Т.Ссылка.Кассир`;
   * `Документ.ОтчетОРозничныхПродажах`: шапка `КассаККМ`, `КоличествоЧеков`, `КоличествоЧековВозврата`;
     ТЧ `Товары` (`Продавец`, `Склад`, `ДисконтнаяКарта`, `ПроцентСкидкиНаценки`) и `ВозвращенныеТовары`;
   * `РегистрНакопления.ТоварыНаСкладах` (`Склад`, `Номенклатура`, `ХарактеристикаНоменклатуры`, `Количество`);
   * `Номенклатура.НоменклатурнаяГруппа`;
   * бренд и цвет товара (для карточек новинок): цвет — реквизит `hiЦвет` (его читает и Sync Admin), бренд — имя реквизита неизвестно, обработка пробует по очереди `hiБренд`, `Бренд`, `Марка`, `Производитель` (`СвойствоНоменклатуры`). Найдите настоящее имя в карточке номенклатуры и поставьте его первым.
   Быстрая проверка запроса — Конструктор запроса (ПКМ по тексту запроса → Конструктор запроса): если поле не найдено,
   конструктор подсветит ошибку.
6. Сохранить: **Файл → Сохранить как** → `C:\awer-sales-bot\onec\ВыгрузкаПродажДляБота.epf`.
7. Проверка: в 1С:Предприятии **Файл → Открыть** → `.epf` → период «вчера» → «Выгрузить».
   В папке появятся четыре файла (`orp_docs`, `sales`, `stock`, `arrivals`); если раздел не выгрузился — `error_*.txt`
   с причиной. Затем `awer-bot import-sales` покажет число строк и продавцов.

## Автозапуск каждый день

База **клиент-серверная** — запуск с `/S"сервер\база"`, а не `/F"папка"` (с `/F` 1С базу не откроет).

**1. Пользователь 1С «Бот»** (Конфигуратор → Администрирование → Пользователи):
* роль только на чтение: чеки ККМ, отчёты о розничных продажах, регистр «Товары на складах», справочники
  (номенклатура, склады, кассы, продавцы, дисконтные карты), документы-регистраторы поступлений;
  право «Открытие внешних обработок»;
* **снять «Защита от опасных действий»** — иначе запуск `.epf` ждёт подтверждения человека;
* «Аутентификация операционной системы» — указать учётную запись Windows, под которой будет работать задача.
  Тогда пароль 1С не нужен вовсе и не виден в Планировщике.

**2. Задача Планировщика** — скрипт (PowerShell от администратора, из папки проекта):
```
.\scripts\install-1c-task.ps1 -Base "localhost\<имя базы>"
```
Он спросит пароль учётной записи Windows (его хранит Windows) и создаст задачу «AwerSalesBot-1C»:
каждый день в 07:30, не дольше 30 минут, пропущенный запуск — при включении компьютера. Команда задачи:
```
"C:\Program Files\1cv8\8.3.9.2233\bin\1cv8.exe" ENTERPRISE /S"localhost\<имя базы>" /WA+
   /Execute"C:\awer-sales-bot\onec\ВыгрузкаПродажДляБота.epf" /C"AUTO" /DisableStartupMessages /DisableStartupDialogs
```
* `/C"AUTO"` — латиницей: кириллица портится в задачах и .bat. Обработка выгружает вчера и позавчера и
  закрывает 1С.
* `/DisableStartupDialogs` обязателен: без него при нехватке лицензий 1С ждёт ответа человека, процессы копятся.
* Если всё же нужен вход по паролю — `/N"Бот" /P"пароль"` вместо `/WA+`, но тогда пароль виден всем, кто
  открывает Планировщик.

**3. Проверка:** Планировщик заданий → «AwerSalesBot-1C» → «Выполнить». Через пару минут в `data\inbox`
появятся файлы. Если раздел не выгрузился (например, неверное имя реквизита), рядом появится `error_*.txt` —
бот перешлёт его текст владельцу в MAX.

Время запуска 1С — раньше `schedule.daily_send_time` бота (по умолчанию 09:30); если файла нет — бот ждёт
и повторяет каждые 30 минут до 13:00. Той же базой пользуется Sync Admin: обработка бота — ещё один сеанс и
лицензия на несколько минут; остатки и поступления отбираются по складам магазинов прямо в запросе.

Ручной вариант: утром открыть обработку и нажать «Выгрузить».

## История продаж из 1С и проверка плана

План месяца берётся из трёх прошлых месяцев и того же месяца год назад. Пока история только из ведомостей
зарплаты, в ней нет мая–июня 2025 и половины июля и сентября 2025 — коэффициент год к году на август и сентябрь
2026 получается по одному-двум месяцам и неточен. Поэтому один раз выгрузите продажи из 1С за прошлые месяцы:

1. Открыть обработку вручную, **период — целые месяцы**, например 01.05.2025 – 31.10.2026 (можно частями по
   кварталам). Месяц, за который есть хоть один день из 1С, считается по 1С целиком — неполный месяц исказит план.
2. Источник — «Чеки»; если чеки за прошлый год в базе не хранятся — «ОРП».
3. Файлы — в папку входящих бота; бот загрузит их при следующем запуске рассылки (или `awer-bot import-sales`).
4. Админка → «Продавцы» → «Имена в 1С»: объединить, если один человек записан по-разному; тех, кто уже не
   работает, — «Уволить» (они появятся в списке «Ждут подключения»).
5. Админка → **«Проверка плана»**: с 2026-08 по 2026-10 — какой план бот поставил бы каждому по данным до начала
   месяца, факт, выполнение и ставка по схеме; «Скачать в Excel». Ничего не сохраняется и не отправляется.
   То же в консоли: `awer-bot backtest 2026-08 2026-10`.

## Если 1С и бот на разных компьютерах

`КаталогВыгрузки` — сетевая папка (`\\сервер\awer-inbox`), которую бот видит как `onec.inbox`.
(Есть и приём файла по HTTP — `POST /api/upload` с заголовком `X-Token`, если понадобится.)
