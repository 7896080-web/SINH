# Внешняя обработка 1С «ВыгрузкаПродажДляБота»

База: обычное приложение (обычные формы). Продажи по продавцам есть в двух местах, обработка выгружает оба:
* **«Отчет о розничных продажах»** (ОРП) → `sales_*.csv` — **деньги**: план, выполнение, ступени, ставка, выручка
  магазина (решение владельца 19.10.2026: за истину принимаем отчёт — подарочные сертификаты и возвраты там верны).
  Возврат уменьшает день, когда вернули; прошлый период не пересчитывается.
* **чеки ККМ** (`Документ.ЧекККМ`) → `receipts_*.csv` — только показатели: средний чек, вещей в чеке, доля чеков
  «одна вещь», лучшие часы, что берут вместе. Если чеков за какие-то дни нет, средний чек и вещей в чеке бот
  считает по магазину (шапки ОРП), а по продавцу — по покупкам с дисконтной картой.

Бот каждый день сверяет строки ОРП с итогом ОРП по магазину; если расхождение больше 1 000 ₽ — пишет владельцу.

Исходники: `onec/ВыгрузкаПродажДляБота/МодульОбъекта.bsl`, `МодульФормы.bsl`.
Собирается в Конфигураторе в `ВыгрузкаПродажДляБота.epf` (бинарник в git не храним). Устроена так же, как
обработка Sync Admin «ОбменССайтом», проверенная на этом сервере (8.3.9.2233): обычная форма, обработчик
`ПриОткрытии` привязан в палитре свойств, автозапуск `/Execute … /CAUTO` в интерактивной сессии Windows.

## Что выгружает (CSV, UTF-8, `;`)

| Файл | Содержимое | Зачем |
|---|---|---|
| `orp_docs_*.csv` | Дата;Магазин;Касса;Документ;Чеков;Чеков возврата;Выручка | признак «смена закрыта» (проведённый ОРП), сверка со строками, средний чек магазина, если чеков нет |
| `sales_*.csv` | Дата;Время;Склад;Документ;Чек;Продавец;Номенклатура;Номенклатурная группа;Количество;Цена;Сумма;Скидка;Ручная скидка %;Дисконтная карта — строки ОРП, «Время» и «Чек» пусты | план, ступени, ставка, вещи, скидки; возвраты с минусом; пустой продавец → «(без продавца)» (видно владельцу); «Одежда сотрудникам», «Стажер» (общий вход), «Татьяна» (технические продажи) — в выручке магазина, но без плана и ставки (`onec.service_sellers`) |
| `receipts_*.csv` | те же колонки — строки чеков ККМ с номером чека и временем | средний чек, вещей в чеке, часы продаж, связки товаров; в деньги не входят |
| `stock_*.csv` | Дата;Склад;Номенклатура;Номенклатурная группа;Характеристика;Остаток | советы только по товару в наличии; владельцу — «битые» размеры и залежавшийся товар |
| `arrivals_*.csv` | Дата;Склад;Документ;Номенклатура;Номенклатурная группа;Характеристика;Поступило;Бренд;Цвет | продавцам утром — что пришло нового; в бот «Обучение» — карточка новинок с брендом и цветом |

Скидка = Цена × Количество − Сумма. Ручная скидка — по колонке «% Руч. ск.» (владельцу, продавцам не показывается).
Остатки и поступления — только складов магазинов: `ПодстрокиСкладов` в модуле формы (подстроки через `;`,
по умолчанию `ГОРОД_склад;МСЛ_Склад` — просто «ГОРОД» захватил бы и «ГОРОД_в пути»). Магазин определяется по складу/кассе через `config.yaml → onec.store_map`.

## Сборка в Конфигураторе (10 минут)

Полей и кнопок на форме нет — рисовать ничего не нужно: при открытии обработка сама спрашивает окнами.

1. Конфигуратор базы (можно рабочей — обработка внешняя, конфигурацию не меняет). **Сервис → Параметры →
   Общие → «Управляемое приложение и обычное приложение»** — иначе обычную форму не создать.
2. **Файл → Новый… → Внешняя обработка.** Имя `ВыгрузкаПродажДляБота`, синоним «Выгрузка продаж для бота».
   Реквизиты не нужны.
3. **Действия → Открыть модуль объекта** — стереть всё и вставить `МодульОбъекта.bsl` целиком.
4. **Формы → Добавить (зелёный плюс)** → «Форма обработки», тип **обычная**, галочка «Назначить основной» → Готово.
   Модуль формы (вкладка «Модуль» внизу окна формы) — стереть всё и вставить `МодульФормы.bsl` целиком.
5. **Привязать обработчик:** окно формы → палитра свойств (Alt+Enter) → раздел **События → ПриОткрытии** → выбрать
   `ПриОткрытии` (лупа или выпадающий список). Сам по имени он не подключается — как у Sync Admin.
6. В модуле формы, процедура `ПриОткрытии`: проверить `ПапкаДляБота` (папка `data\inbox` бота).
7. **Файл → Сохранить как** → `C:\awer-sales-bot\onec\ВыгрузкаПродажДляБота.epf`. При сохранении Конфигуратор
   проверит модули; ошибка «не определено» по имени поля — значит, в вашей базе оно называется иначе (шаг 9).
8. **Проверить базу:** 1С:Предприятие → **Файл → Открыть** → `.epf` → «Проверить базу (для настройки обработки)».
   Откроется `check_*.txt` из папки бота: какие документы, реквизиты, склады и кассы есть, сколько чеков хранится
   по месяцам, где бренд товара, и пробный запуск каждого запроса выгрузки за вчера. Только чтение; имён продавцов
   в нём нет. **Пришлите текст файла разработчику** — по нему сверяются имена реквизитов, `ПодстрокиСкладов` и
   `config.yaml → onec.store_map`. Первая проверка — 19.10.2026: все имена сверены (скилл `1c-magazin-odezhdy`).
9. После правок — повторить шаги 3, 4 (вставить модули заново) и 7.
10. **Пробная выгрузка:** Файл → Открыть → `.epf` → «Выгрузить продажи за период» → вчера. В папке
   появятся пять файлов (`orp_docs`, `sales`, `receipts`, `stock`, `arrivals`); если раздел не выгрузился —
   `error_*.txt` с причиной. Бот загрузит их сам при следующей рассылке (или `awer-bot import-sales`).

Без окон, из командной строки: `/Execute"…\ВыгрузкаПродажДляБота.epf" /CCHECK` — отчёт и выход;
`/CAUTO` — выгрузка за вчера и позавчера и выход.

## Автозапуск каждый день

База **клиент-серверная** — запуск с `/S"сервер\база"`, а не `/F"папка"` (с `/F` 1С базу не откроет).

**1. Пользователь 1С «Бот»** (Конфигуратор → Администрирование → Пользователи):
* роль только на чтение: чеки ККМ, отчёты о розничных продажах, регистр «Товары на складах», справочники
  (номенклатура, склады, кассы, продавцы, дисконтные карты), документы-регистраторы поступлений;
  право «Открытие внешних обработок»;
* **снять «Защита от опасных действий»** — иначе запуск `.epf` ждёт подтверждения человека;
* вход по имени и паролю, как у Sync Admin. «Аутентификацию операционной системы» не включать: она связала бы
  учётную запись Windows людей с «Ботом» — кто откроет 1С под ней, войдёт как «Бот» (аудит У4).

**2. Задача Планировщика** — скрипт (PowerShell от администратора, из папки проекта, под той учётной записью
Windows, которая обычно вошла на сервере):
```
.\scripts\install-1c-task.ps1 -Base "localhost\<имя базы>"
```
Задача «AwerSalesBot-1C»: каждый день в 07:30 и повтор в 08:30 (если в 07:30 не хватило лицензии; выгрузка дня
просто заменится), **только для вошедшего пользователя** (толстому клиенту 1С нужна интерактивная сессия Windows —
так же работает Sync Admin; в режиме «без входа пользователя» 1С не запустится), не дольше 15 минут. Команда:
```
"C:\Program Files\1cv8\8.3.9.2233\bin\1cv8.exe" ENTERPRISE /S"localhost\<имя базы>" /WA- /N"Бот" /P"…"
   /Execute"C:\awer-sales-bot\onec\ВыгрузкаПродажДляБота.epf" /CAUTO /DisableStartupDialogs /DisableStartupMessages
```
* `/CAUTO` — латиницей и без кавычек, как `/CEXCHANGE` у Sync Admin. Обработка выгружает вчера и позавчера и
  закрывает 1С.
* `/DisableStartupDialogs` обязателен: без него при нехватке лицензий 1С ждёт ответа человека, процессы копятся.
* Скрипт спросит пароль пользователя 1С «Бот» (другое имя — `-OneCUser`); пароль виден в свойствах задачи — как у
  Sync Admin. Для отдельной учётной записи Windows только под бота можно `-WindowsAuth` (`/WA+`).

**3. Проверка:** Планировщик заданий → «AwerSalesBot-1C» → «Выполнить». Через пару минут в `data\inbox`
появятся файлы. Если раздел не выгрузился (например, неверное имя реквизита), рядом появится `error_*.txt` —
бот перешлёт его текст владельцу в MAX.

Время запуска 1С — раньше `schedule.daily_send_time` бота (по умолчанию 09:30); если файла нет — бот ждёт
и повторяет каждые 30 минут до 13:00. Той же базой пользуется Sync Admin: обработка бота — ещё один сеанс и
лицензия на несколько минут; остатки и поступления отбираются по складам магазинов прямо в запросе.

Ручной вариант: утром открыть обработку → «Выгрузить продажи за период» → вчера.

**Рядом с Sync Admin.** Задачи друг другу не мешают: это отдельные запуски 1С (отдельные сеансы, у бота — свой
пользователь «Бот»), обработка бота только читает, без транзакций и блокировок — проведение перемещений Sync Admin
она не ждёт и не задерживает; папки и файлы разные (`C:\sync\…\*.txt` у Sync Admin, `data\inbox\*.csv` у бота).
Общее у них — лицензии 1С и сервер: выгрузка дня занимает сеанс на 1–2 минуты в 07:30, когда в магазинах ещё
никто не работает; если лицензии не хватит, 1С не зависнет (`/DisableStartupDialogs`), а повторит в 08:30.
Тяжёлые разовые операции — «Проверить базу» и выгрузку истории за много месяцев — делать вечером или до открытия.

## История продаж из 1С и проверка плана

План месяца берётся из трёх прошлых месяцев и того же месяца год назад. Пока история только из ведомостей
зарплаты, в ней нет мая–июня 2025 и половины июля и сентября 2025 — коэффициент год к году на август и сентябрь
2026 получается по одному-двум месяцам и неточен. Поэтому один раз выгрузите продажи из 1С за прошлые месяцы:

1. Открыть обработку вручную, **период — целые месяцы**, например 01.05.2025 – 31.10.2026 (можно частями по
   кварталам). Месяц, за который есть хоть один день из 1С, считается по 1С целиком — неполный месяц исказит план.
2. Обработка выгрузит строки ОРП (`sales_*`) и чеки (`receipts_*`). Старые файлы `sales_*`, выгруженные прежней
   обработкой из чеков, бот распознает как чеки: деньги для плана из них не берутся — выгрузите период заново.
3. Файлы — в папку входящих бота; бот загрузит их при следующем запуске рассылки (или `awer-bot import-sales`).
4. Админка → «Продавцы» → «Имена в 1С»: объединить, если один человек записан по-разному; тех, кто уже не
   работает, — «Уволить» (они появятся в списке «Ждут подключения»).
5. Админка → **«Проверка плана»**: с 2026-08 по 2026-10 — какой план бот поставил бы каждому по данным до начала
   месяца, факт, выполнение и ставка по схеме; «Скачать в Excel». Ничего не сохраняется и не отправляется.
   То же в консоли: `awer-bot backtest 2026-08 2026-10`.

## Если 1С и бот на разных компьютерах

`КаталогВыгрузки` — сетевая папка (`\\сервер\awer-inbox`), которую бот видит как `onec.inbox`.
(Есть и приём файла по HTTP — `POST /api/upload` с заголовком `X-Token`, если понадобится.)
