# CLAUDE.md — awer-sales-bot

Контекст для работы в Claude Code. Отвечай по-русски; владелец — не программист, объясняй результат, а не код.

## Что это
Система мотивации продавцов розницы AWER (магазины «Город» и «МСЛ», ТРЦ «Меганом», Симферополь):
* индивидуальный базовый план каждому продавцу (прошлый год × тренд, с сезонностью — docs/SPEC.md);
* ставка 25 000 + 5 000 за каждые +10 % сверх плана (макс. 45 000); старшим (админам) фиксированная доплата 13 000;
* ежедневно, на следующий день после закрытия дня, бот в мессенджере **MAX** присылает продавцу: базовый план,
  сколько до базы, сколько до следующей ступени, средний чек, комплектность, совет;
* данные — из **1С** (внешняя обработка `onec/`, выгрузка CSV строк чеков);
* админка (локальный веб) — ручная правка коэффициента год к году, шага %, надбавки, базы, максимума, личных планов.

## Структура
```
src/awer_sales_bot/
  planning/engine.py    # ЧИСТЫЕ функции расчёта — эталон, покрыт регрессией по Excel-модели
  planning/service.py   # настройки месяца, ручные правки, фиксация плана, статус продавца, итоги месяца
  importers/onec_sales.py      # CSV/XLSX из 1С → sales_lines, imported_days («день закрыт»)
  importers/payroll_archive.py # стартовая история из ведомостей ЗП (xlsx «Аванс…», «ЗП…»)
  metrics.py            # средний чек, вещей в чеке, возвраты, «что докупают вместе»
  recommendations.py    # правила советов (+ опционально Claude API)
  messages.py           # тексты сообщений
  max_api.py, bot.py    # клиент MAX, long polling, привязка по коду, команды
  jobs.py               # ежедневная рассылка, 1-е число: итоги + новый план
  web.py                # админка FastAPI (+ /api/upload для 1С)
  cli.py                # awer-bot <команда>
onec/ВыгрузкаПродажДляБота/  # исходники внешней обработки 1С (BSL) — собирать в Конфигураторе (docs/1C.md)
tests/                  # pytest; fixtures/history_anon.json — обезличенная история июль 2025 – сен 2026
```

## Правила
* Любое изменение расчёта — сначала в `docs/SPEC.md`, затем в `engine.py`, и `tests/test_engine.py` должен проходить.
  Эталонные цифры октября 2026 (тренд 0,805, план магазина 5 605 452, Эльвина 1 107 673) менять нельзя без согласования.
* Ручные значения из админки всегда главнее расчёта; пустое поле = расчёт.
* План месяца фиксируется 1-го числа (`plans`) — сообщения берут только зафиксированный.
* Админ. доплата не участвует в шагах и не меняется схемой.
* Имена продавцов — как в 1С; «Фамилия Имя МСЛ» = тот же продавец в точке МСЛ (`seller_store_suffixes`).
* Секреты только в `.env`. Реальные данные продавцов не коммитить (репозиторий приватный, data/ в .gitignore).
* Запуск тестов: `pytest -q`.
