# План и ставка

Эталон — Excel-модель владельца «План_и_ставка_продавцов.xlsx», согласованная 18.10.2026. Код воспроизводит её до
рубля. Ошибка здесь — это неверная зарплата живому человеку.

## Порядок любой правки

1. Сначала `docs/SPEC.md` — правило словами. Если правило новое — это решение владельца, не программиста:
   спроси, прежде чем писать код.
2. Потом `planning/engine.py` — только чистые функции, без базы и дат «сегодня».
3. `tests/test_engine.py` должен проходить без изменения эталонных цифр октября 2026:
   тренд 0,805; план магазина 6 963 861 × 0,805 = 5 605 452; коэффициент 1,083; Эльвина 1 107 673;
   Юлия 941 654; Добряк 706 013; новичок 449 146. Менять их — только с согласия владельца.
4. `pytest -q`, затем `awer-bot plan YYYY-MM` на реальной базе и сравнить с Excel.

## Правила, которые нельзя сломать

* Ручное значение из админки главнее расчёта; пустое поле = расчёт (`month_settings`, `plan_overrides`).
* План месяца фиксируется 1-го числа в `plans`; сообщения берут зафиксированный план.
* Продавец, появившийся после фиксации, получает **одну** строку с планом новичка (`service.ensure_plans`);
  планы остальных при этом не пересчитываются. Полная перефиксация (`freeze`) меняет цели всем — только по
  решению владельца.
* Ставка = min(максимум; база + надбавка × полные шаги сверх плана) + доплата старшим. Доплата не участвует
  в шагах и схемой не меняется.
* Выполнение = (продажи / отработано) / план, где отработано = смены / норма (18). Это «за смену», не «за месяц».
* Базовый план на месяц в сообщениях = план × (отработанные + смены по графику впереди) / 18 — к концу месяца
  совпадает с выполнением для ставки. График — таблица `schedule`, админка «График смен».
* Продажи без продавца входят в выторг магазина (тренд, план магазина), но ни в чей личный план.
* Квизы, рекорды, цель недели, уроки на ставку не влияют.
