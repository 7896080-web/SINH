# Тон сообщений продавцам

## Как писать

* Термины владельца: выход продавца — **рабочий день**; **смена** — состав продавцов одного магазина.
  Никогда не «смена» в значении рабочего дня.

* На «вы», по имени из `sellers.first_name`. Коротко: одно утреннее сообщение читается за 30 секунд.
* Сначала факт, потом что делать. Одно действие на совет, без списка из пяти пунктов.
* Без укоров и давления: «Чтобы выйти на план, нужно ≈ 38 000 ₽ в рабочий день», а не «Вы отстаёте».
* Хорошее — называть: рекорды, серии, выполненная цель недели. Признание работает, когда оно конкретное
  («личный рекорд — 85 000 ₽ за рабочий день»), а не общее («молодец»).
* Цифры — через функции `rub()`, `pct()`, `d1()` из `messages.py`: пробел между разрядами, запятая в дробях.
* Разметка MAX — markdown: только `**жирный**`. В данных (названия товаров, категорий) не бывает `*` и `_` —
  если появятся, экранируй, иначе сообщение может прийти разломанным.
* Одно сообщение — до 4 000 символов. Урок, квиз, листок для старшего — отдельными сообщениями.

## Кто что видит

| Кто | Видит | Не видит |
|---|---|---|
| Продавец | личный план и личные показатели; рядом — среднее по команде без админов; средний чек магазинов, только если чеков нет (по продавцу его не посчитать); своя доля ручных скидок — только в цели недели и совете, если выше команды (аудит П2) | цифры и имена коллег, общий план магазинов, суммы ручных скидок, рейтинги |
| Старший (роль `admin`) | свои цифры; по понедельникам листок по каждому продавцу для разговора 1:1 | ставки и ведомость других |
| Тестовая карточка (роль `test`, «Татьяна») | то же, что продавец — владелец проверяет бота на себе | сама не входит в средние по команде, ведомость, «Кого похвалить» |
| Владелец (`max.owners`) | всё: сводка по людям, ручные скидки, продажи без продавца, «кого похвалить» | — |

* Никогда не сравнивать продавца с коллегой по имени в его сообщении.
* Публичного рейтинга нет: последние места демотивируют сильнее, чем мотивируют первые.

## Деньги и награды

* Ставка зависит только от выполнения личного плана по выручке (решение владельца 18.10.2026, `docs/SPEC.md`).
  Чек, вещи, скидки, квизы — информационные.
* Награды за качество продаж — нематериальные: рекорды, серии, цель недели, похвала владельца.
* В сообщениях не обещать денег, кроме ставки по схеме.
* Продавцу — личный план и личные показатели. Общий план магазинов продавцам не показываем, только владельцу
  (решение владельца 18.10.2026).

## Персональные данные

* В Claude API (`recommendations.llm`) — только текст совета с цифрами, без ФИО и без названия магазина.
* В журнал `message_log` текст пишется целиком — он хранится только на компьютере магазина.

## Перед коммитом

* `pytest -q` — тесты проверяют ключевые строки сообщений.
* `awer-bot daily --dry-run --force` — прочитать глазами, как сообщение выглядит целиком.
