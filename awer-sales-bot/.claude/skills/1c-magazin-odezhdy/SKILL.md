# 1С «Магазин одежды и обуви» для awer-sales-bot

Сверено 18.10.2026 с тем, что Sync Admin уже проверил на этой же базе (`../1c/README.md`,
`../1c/ТЗ_ОбменССайтом.md`, `../README.md` раздел «Реальные имена», `../ПЕРЕДАЧА_В_ВЕБ.md` — пути от корня
awer-sales-bot внутри репозитория SINH).

## База

* Конфигурация «NEW Магазин одежды и обуви» 1.0.16.1 (доработанная: реквизиты с префиксом `hi`), платформа 8.3.9.2233,
  **обычное приложение** (обычные формы). Отчёт «Проверка базы» обработки (`check_*.txt`) — источник сверенных имён.
* **Клиент-серверная** база `localhost\<база-1С>` на том же сервере, что и Sync Admin. Запуск — `/S"localhost\<база-1С>"`,
  а не `/F"…"` (в старых комментариях обработки было `/F` — ошибка).
* Той же базой пользуется обработка Sync Admin «ОбменССайтом» — запуск толстого клиента раз в 1–2 минуты.
  Каждый запуск занимает сеанс и лицензию.

## Язык запросов 8.3.9 — ошибки, которые уже делали

* `ПРЕДСТАВЛЕНИЕ(...)` нельзя использовать внутри выражений (`ПРЕДСТАВЛЕНИЕ(X) + " " + Y`), в условиях и, вероятно,
  в `СГРУППИРОВАТЬ ПО`: представление вычисляется после выполнения запроса. Выбирай ссылку и поле отдельно,
  склеивай строку в BSL при обходе выборки.
* Фильтруй в запросе, а не в памяти: `ГДЕ Склад В (&Склады)` или `Склад.Магазин В (&Магазины)`. В базе около
  150 тыс. номенклатуры — остатки по всем складам с `ПРЕДСТАВЛЕНИЕ` на каждую строку тяжелы для общего сервера.
* Если в базе есть ограничения доступа на уровне записей, пиши `ВЫБРАТЬ РАЗРЕШЕННЫЕ`.
* `Найти()` устарела, но работает; `СтрНайти` на 8.3.9 тоже есть.
* Псевдоним таблицы `В` — служебное слово языка запросов («В списке»): «Ожидается имя». Брать `ВТ`, `Д`, `Т`.
* Не вызывать метод прямо у конструктора: `Новый Файл(Путь).Существует()` → Конфигуратор 8.3.9 сбивается
  («Обнаружено логическое завершение исходного текста модуля» далеко ниже по тексту). Писать в две строки:
  `Ф = Новый Файл(Путь); Если Ф.Существует() Тогда` — как в обработке Sync Admin.
* Окна (`Предупреждение`, `ВвестиДату`, `ВыбратьЭлемент`) и `ПараметрЗапуска` — только в модуле формы: модуль объекта
  компилируется и для сервера.
* Системное перечисление для `ВвестиДату` — `ЧастиДаты.Дата` (множественное число); `ЧастьДаты` — «Переменная не
  определена».

## Обработка: сборка

Как у Sync Admin «ОбменССайтом» (проверено на сервере 8.3.9.2233, `../ДОКУМЕНТАЦИЯ.md` §9):
1. Конфигуратор → Сервис → Параметры → «Управляемое приложение и обычное приложение» — иначе обычную форму не создать.
2. Новая внешняя обработка `ВыгрузкаПродажДляБота`, реквизитов нет, модуль объекта — `onec/…/МодульОбъекта.bsl`
   (только общий и серверный код: окна вопросов там не компилируются для сервера).
3. Обычная форма, основная, без полей и кнопок, модуль — `МодульФормы.bsl`; обработчик **`ПриОткрытии` привязать
   в палитре свойств** (События) — по имени он не подключается. Настройки (`ПапкаДляБота`, `ИсточникПродаж`,
   `ПодстрокиСкладов`) — в `ПриОткрытии`.
4. Режимы по `ПараметрЗапуска`: `AUTO` (выгрузка вчера+позавчера, выход), `CHECK` (отчёт `check_*.txt`, выход),
   пусто — окна: «Выгрузить за период» / «Проверить базу». Отчёт «Проверка базы» — первый шаг настройки: по нему
   переносить имена из «не проверено» в «проверено».
5. `.epf` в git не хранится (`.gitignore`), хранятся исходники `.bsl`.

## Файл для бота (контракт с `importers/onec_sales.py`)

* CSV, разделитель `;`, `ЗаписьТекста(…, КодировкаТекста.UTF8)` пишет с BOM — Python читает `utf-8-sig`. Не менять.
* Дата `Формат(Д, "ДФ=dd.MM.yyyy")`, время `"ДФ=HH:mm"`, числа `Формат(Ч, "ЧРД=.; ЧГ=0; ЧН=0")` — без пробелов
  между разрядами.
* В значениях заменять `;`, перевод строки, возврат каретки и **двойную кавычку**: строка, начинающаяся с `"`,
  склеит в Python все следующие строки файла в одну.
* Писать во временный файл `*.part`, затем `ПереместитьФайл` в итоговое имя — бот не должен прочитать
  недописанный файл (так делает Sync Admin).
* Имена колонок — в `config.yaml → onec.columns` / `doc_columns` / `stock_columns`. Меняешь колонку — меняй обе
  стороны в одном коммите и прогоняй `pytest -q`.
* Пустой продавец — это продажа «без продавца», её нельзя терять: в `onec.exclude_sellers` не должно быть `""`.
* Ошибка раздела выгрузки — файл `error_<время>_<раздел>.txt` (тоже через `.part`); бот пересылает его текст
  владельцу (`import_inbox` → `jobs.daily_run`). Разделы выгружаются независимо, в `Попытка`.

## Автозапуск без человека

```
"C:\Program Files\1cv8\8.3.9.2233\bin\1cv8.exe" ENTERPRISE /S"localhost\<база-1С>" /WA+
  /Execute"C:\awer-sales-bot\onec\ВыгрузкаПродажДляБота.epf" /CAUTO /DisableStartupDialogs /DisableStartupMessages
```
* Параметр запуска латиницей и без кавычек (`/CAUTO`, как `/CEXCHANGE` у Sync Admin): кириллица портится в .bat
  и в задачах Планировщика.
* **Нужна интерактивная сессия Windows** (проверено Sync Admin): задача «только для вошедшего пользователя»;
  в режиме «без входа пользователя» толстый клиент не запускается.
* `/DisableStartupDialogs` обязателен: без него при нехватке лицензий или вопросе платформы процесс зависнет
  навсегда, и такие процессы будут копиться.
* Пользователь «Бот»: права на чтение чеков/ОРП, регистров, справочников, документов-регистраторов, право
  открывать внешние обработки; **снять «Защиту от опасных действий»** (с 8.3.9.2033), иначе запуск .epf ждёт
  подтверждения.
* Пароль не хранить в открытом виде в задаче, если можно — аутентификация Windows (`/WA+`).
* Задача Планировщика: «Остановить, если выполняется дольше 30 минут».
* Ошибки в режиме автозапуска пишутся в журнал регистрации 1С (`ВыгрузкаПродажДляБота`) и файлом `error_*.txt`
  в папку бота. Задачу создаёт `scripts/install-1c-task.ps1`.

## Чего не делать

* Не писать в базу 1С из awer-sales-bot — обработка только читает.
* Не проверять на рабочей базе то, что можно проверить на копии; первый прогон — на копии.
* Не трогать обработку Sync Admin «ОбменССайтом» и её файлы (`stock_*.txt`, `.part`) — у неё свои правила
  (`../CLAUDE.md`).
