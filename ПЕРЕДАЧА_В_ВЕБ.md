# sync_admin — передача проекта (для продолжения в веб-версии Claude Code)

Дата: 2026-09-16. Это мастер-документ. Приложите **весь этот архив релиза** к новой веб-сессии
Claude Code — в нём собран текущий код + вся история решений.

## 1. Что это за проект
FastAPI-приложение `sync_admin`: синхронизирует остатки между 1С «Магазин одежды и обуви»
и маркетплейсами (Wildberries, Ozon, Kit/«Сайт AWER») через файловый обмен с 1С (.epf) по
локальным папкам. FBS-модель. Ключ сопоставления везде — **баркод**.

## 2. Где что развёрнуто (ВАЖНО)
- **Сервер приложения:** другой компьютер `WIN-Q0QVP2SM59L`, путь `C:\sync_admin`. 1С-база
  `localhost\modus_new`, конфигурация «Магазин одежды и обуви» 1.0.16.x, платформа 8.3.9.2233.
- **Мои инструменты (и локальный терминал) на другой машине (MonoR)** — прямого доступа к
  `C:\sync_admin` НЕТ. Деплой только через base64-патчи, которые вы вставляете в PowerShell
  **на сервере**.
- Службы NSSM: `sync_admin_web` (порт 8000) и `sync_admin_worker` (планировщик).
- Обмен с 1С: `C:\sync\{tasks,results,archive}`, UTF-8, разделитель `|`.

## 3. Механика деплоя (как накатывать правки на сервер)
Патч = `zlib.compress + base64`, разбитый на 2 части по 80 символов в here-string, с проверкой
SHA256 каждой части и полного b64. На сервере:
1. Функция `Hx` считает SHA256 строки (НЕ `H` — конфликт с алиасом Get-History).
2. Вставляете `$p1`/`$p2` (here-string `@'…'@`, закрывающий `'@` в НАЧАЛЕ строки), чистите
   пробелы `-replace "\s",""`, сверяете `Hx`.
3. Склейка → полный SHA → распаковка через python → запуск apply-скрипта (печатает `ok`/`skip`/
   `MISS` по файлам + `DONE N`).
4. `nssm restart sync_admin_worker` (и `sync_admin_web` при правках web/шаблонов/моделей).

Патчи-генераторы: `gen_patch*.py` в скретчпаде (get_grouped_opcodes или точные якоря из
`repr` с сервера — серверные файлы местами БЕЗ docstring/минифицированы, поэтому якоря брать
`repr`-дампом с сервера, не из релиза). **Крупные фичи безопаснее слать whole-file.**

## 4. Что УЖЕ развёрнуто и работает (эта сессия)
- **Бэкфилл «старт задним числом»** (/testing): тянет реальные FBS-заказы с даты, проводит
  перемещения в 1С их реальной датой. 8-е поле CREATE_MOVEMENT = дата документа.
- **Отбор-гейт**: `SyncSetting.enabled` — настоящий гейт живого поллера (выключенные тихо
  пропускаются).
- **Ручной остаток `transmit_override`** + его «дыхание» на складскую дельту сверки (legacy —
  заменяется порогом, см. §6).
- **Единая дата старта** `broadcast_active_since`.
- **Kit 429**: троттлинг 0.25с.
- **WB каталог**: исправлена пагинация v2 cards/list (грузилось 617/3228 → теперь всё 3228).
- **Пул-матчинг** каталога по цвето-размерному SKU (external_id nmID:chrtID).
- **Полный справочник 1С раз в неделю** (`import_barcode_dict(full=True)`, самоопределение по
  метке `WorkerHeartbeat('import_barcodes_full')`; частый прогон — фильтрованный). Дал
  6500 → 154227 баркодов, конфликты 2444 → 8.
- **Отмены — только НАШИ** (pm11): WB `supplierStatus=cancel`; Ozon `cancellation_initiator=Seller`
  и `not cancelled_after_ship`; Kit — авто-реверс отключён (API не отдаёт инициатора). Клиентские
  отмены после отгрузки НЕ реверсим — возврат идёт из 1С отдельно и подтягивается сверкой.

## 6. НЕ РАЗВЁРНУТО — фича «Порог трансляции» (готова в этом релизе, pm12)
Заменяет дрейфующую ручную цифру фиксированной зависимостью:
- новое поле `Product.broadcast_offset` (nullable int, может быть ±);
- **порог = (остаток ЦС на дату) − (доступно на дату)**; трансляция = `max(0, stock_on_hand − порог)`;
- заказы/сверка двигают только `stock_on_hand`, порог фиксирован → **не дрейфует**;
- приоритетнее `transmit_override` (legacy сохранён);
- UI /testing: два поля «доступно на дату» + «остаток ЦС на дату» → порог считается сам; показ
  «сейчас передаётся на площадки».
- Затронуто: `app/models.py`, `alembic/versions/c1f5a9d2e3b4_product_broadcast_offset.py`,
  `app/workers/dispatch.py`, `app/routers/stock_control.py`, `app/routers/testing.py`,
  `app/templates/testing.html`. Тесты: `tests/test_broadcast_offset.py` (9 шт).
- **Как развернуть из веба:** собрать патч (или whole-file) этих файлов + записать миграцию →
  на сервере применить → `& C:\sync_admin\.venv\Scripts\python.exe -m alembic upgrade head` →
  `nssm restart sync_admin_web` и `sync_admin_worker` → выставить порог=11 для тестового товара
  (`Product.broadcast_offset = 11`, `transmit_override = None`).
- Состояние тестового товара на момент передачи: `transmit_override=44` (перекошено тест-чехардой),
  `stock_on_hand=38`. После деплоя порога и стабилизации ЦС до реальных 29 → трансляция 18.

## 9. Ключевые правила (не сломать)
- Вариант A складов: резерв=продажа уходит СРАЗУ в основной склад площадки
  (Wildberries_Склад_FBO / OZON_Склад / «Сайт AWER»), источник — «ЦС Склад».
- Отмены — только наши (§4). Возвраты — отдельно через 1С.
- Ключ сопоставления — баркод. `processed_at` в БД — UTC.
- Гейт и вся логика крутятся в **worker** — после правок воркера обязателен рестарт.

  Снимает реальные `ProcessedOrder` (кроме `TEST-`), задания 1С и аномалии по ним, очередь
  рассылки и живой журнал товара — для повторного прогона бэкфилла после удаления документов
  в 1С. Остаток не трогает (его выравнивает сверка), требует галочку, отказывает при
  незавершённых заданиях 1С.
- **pm15 (развёрнуто) — БАГ КАНАЛА 1С:** обработка пишет `result_/stock_/barcodes_` через
  `ЗаписьТекста(…, КодировкаТекста.UTF8)`, то есть **с BOM** (подтверждено на сервере: `EF BB BF`).
  Приложение читало их как чистый utf-8 → BOM прилипал к первому полю ПЕРВОЙ строки, и первое
  задание каждого `result_*.txt` не сопоставлялось (висело `sent` при созданном в 1С документе).
  Теперь `utf-8-sig`. Там же: карточка «Порог трансляции» честно показывает 0 и подсказку, если
  `broadcast_enabled=False`.
- **pm16 (развёрнуто):** `apply_result_batch` принимает опоздавший результат и для задания в
  статусе `timeout` (иначе после 15-мин окна ответ 1С уже некуда положить). `build_scheduler`:
  `ftp_send_export_request` и `reconciliation` получают `next_run_time` в первую минуту после
  старта — раньше каждый рестарт воркера сдвигал их на час, и остаток ЦС отставал от 1С.
- **Прогон 16.09 (после сброса):** 9 перемещений проведены реальными датами (11.08…14.09),
  в 1С `ЦБ000000186…194`, плюс 5 шт на сторонний склад 07.09 → ЦС 43 − 14 = **29**, трансляция
  с порогом 11 = **18**. Бэкдейтинг в 1С подтверждён отчётом «Движения товара» — пункт (A)
  из СТАТУС_ГОТОВНОСТИ.md закрыт.
- **Грабли для оператора (устранены в pm17):** «порог кабинета» (`min_threshold`, страховой
  буфер, на кабинетах 1 и 5 стоит 32 — стоит вернуть 0) ≠ «порог трансляции»
